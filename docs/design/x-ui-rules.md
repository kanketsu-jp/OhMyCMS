# X (旧Twitter) 由来 — OhMyCMS 管理画面デザイン規約

調査日: 2026-08-13。方針: OhMyCMSは「できること・ページ構成」はDirectus、「デザイン（見た目・操作感）」はXを参考にする。本ドキュメントはX Web UIを数値・規則として再現可能な形に落とすもの。

**前提条件（必ず読む）**:
- 材料は (1) ローカルスクリーンショット `~/Downloads/X web Apr 2026/`（560枚中、一覧把握のうえ約23枚を実際にRead）と (2) Mobbin MCP（`x-web-40d9ec6f-9b08-4429-a30c-4d3e926218bd`、`search_screens`が使用可、`search_flows`/`search_sections`は未使用）から約36枚を取得、の2系統。合計約59枚を目視した。
- **本調査はスクリーンショットの目視のみで、ブラウザDevToolsによる実測（px計測）は一切行っていない。** 絶対px値の多くは「目測」であり、断定ではない。ローカルファイルは全て `1920×1320px`（デスクトップ幅キャプチャ、`sips`で確認済み）。
- 画像から読み取れないものは「未確認」と明記する。推測を事実として書かない。
- 既存プロジェクト実測（`docs/research/ja-en-ui-evidence.md`）: Tailwind v4 + shadcn/ui（`components.json`: style=`base-nova`, baseColor=`neutral`, iconLibrary=`lucide`）。本書のTailwindクラスはこの構成を前提にする。

## 3. 観察結果（背景と狙いの1〜11に対応）

### 3.1 レイアウト（3カラム構成）

- 3カラム構成（左ナビ／中央コンテンツ／右サイドバー）は、mobbinで取得したhome/settings/profile/notifications/communities/search/DM系すべてで一貫して確認できた。左ナビが最も細い帯、中央カラムが最も広い帯、右サイドバーは中央より狭いが左ナビより広い帯、という相対関係は目視で確認できるが、**絶対px値（最大幅を含む）は今回の調査手段（画像目視のみ、DevTools未使用）では計測できず未確認**。
- 幅が狭くなった時の崩れ方について、「①右サイドバー→②左ナビのラベル→…」という順序で連続的に狭めていく比較画像は入手できなかった（**未確認**）。ただし以下の傍証がある:
  - Chat（メッセージ）機能では、左ナビが**ラベル無しのアイコンのみ**に切り替わっている（ローカル `X web Apr 2026 240.png`、mobbin DM screens 3枚）。Chatは「会話一覧」と「スレッド」の2ペインを中央領域に必要とするため、外側の左ナビが先にラベルを失う設計と推測できる。
  - `Confirm Passcode`のようなフルスクリーン系ユーティリティ画面（ローカル `X web Apr 2026 190.png`）でも左ナビはアイコンのみ。
  - これらはウィンドウ幅を絞った結果ではなく**機能固有のレイアウト**である可能性が高く、「画面幅による責任ある収縮順序」の直接証拠にはならない。断定を避け、OhMyCMSでは独自にブレークポイントを設計し実機検証する必要がある。

### 3.2 ナビゲーション

- 左ナビの各項目はアイコン+ラベルの横並びで、行間は目視でゆったり（縦の密度は低め）。アクティブ状態は**アイコンのfill/outline切り替え**（例: Homeが現在地だとhouseアイコンが塗りつぶし、他ページでは中抜き）で表現されており、背景色によるハイライト（pill/box）の有無は今回のスクショ群からは確認できなかった（**未確認**）。
- 通知バッジは青地丸+白文字の小バッジがベルアイコン右上に重なる形（ローカル `X web Apr 2026 140.png`）。
- Postボタンはナビ項目群の下、単独で配置。黒地白文字pill、ダークモードでは白地黒文字に反転（ローカル `X web Apr 2026 540.png`）。
- モバイルのWeb版下部タブバーは、ローカル560枚中の目視サンプリングおよびMobbin検索（`platform: web`）のいずれからも実例を発見できず**未確認**。ネイティブアプリの下部タブ構成は一般に知られているが、本調査はWeb版が対象のため対象外とする。

### 3.3 ボタン

- Primaryボタン（Post/Follow/Save/Publish/Log out/Continue to X/Next等）は共通して**完全な角丸(pill)**。ライトモードは黒地白文字、ダークモードは白地黒文字に反転（ローカル `540`）。
- Secondaryボタン（Cancel）は白地+細いグレーボーダー+黒文字、同じくpill形状（ローカル `460`）。
- 破壊的操作（削除等）を赤塗りのボタンにしている例は今回確認できなかった。ローカル `290`（Hiringテーブルのゴミ箱アイコン）は他のアクションアイコンと同系色。mobbin Community設定の「Delete Community」はテキストリンクとして赤文字表示されるのみで、ボタン化されていない。→ **Xは破壊的操作をPrimaryボタン化しない傾向**が観察される。
- Ghost/テキストボタン（"Save"＝ローカル `45` content warningモーダルのヘッダ右上、"Done"＝ローカル `390`）は背景なし・青文字。ヘッダ右上に頻出するパターン。
- モーダル・カードの角丸は大きめ（目測16〜24px程度）。入力欄もボーダー付きの角丸。

### 3.4 タップターゲット

- アイコンのみボタン（いいね・リポスト・返信・ブックマーク・共有）は、周囲に視覚的な余白（パディング）が確保されているように見える。ホバー時の円形背景色変化はXの既知挙動として一般的に語られるが、**静止画からは直接確認できず未確認**。
- モーダルの閉じるボタン（×）は左上/右上に十分な余白を伴って配置（ローカル `45`, `90`）。
- チェックボックス自体の見た目は小さい（目測18〜20px）が、行全体（タイトル+説明文込み）がクリック領域になっているように見える（ローカル `45` の "Nudity/Violence/Sensitive"、`440` の "Protect your posts" 行）。
- 結論: 「アイコンの見た目より当たり判定が大きい」という仮説は、静止画からのピクセル計測ができないため**厳密には未確認**。ただし状況証拠（行全体のクリック領域化、余白の視覚的確保）は複数見つかっており、方向性としては妥当と判断する。

### 3.5 区切り

- 設定リスト（Settings, Admin tools, Audience設定）は「カードで囲む」のではなく、行間の余白または極細の罫線のみで区切るフラットデザイン。影(shadow)はほぼ使われていない（**目視ベースでの「未確認」寄りの観察**、計測はしていない）。
- カード型が使われる箇所: Hiringテーブルの行（ローカル `290`）、Communitiesのサムネイルカード（ローカル `340`）、ツイート埋め込み/引用カード（ローカル `45`）。
- モーダル自体は背景から浮くための濃いオーバーレイ（黒/グレー、不透明度高め）を伴う（ローカル `5, 20, 45, 90, 460, 559` 全てで確認）。
- 区切り線は極細（目測1px相当）、薄いグレー。

### 3.6 余白

- 目視で見る限り、間隔の大小に一貫した規則性があるように見える（ナビアイコンの縦間隔、モーダル内padding、ボタン内paddingが概ね揃って見える）。ただし**4の倍数か8の倍数かを実測で判定することはできず未確認**。OhMyCMSでは既存のTailwindデフォルトスケール（4px刻み）をそのまま採用する。

### 3.7 タイポグラフィ

- モーダルタイトル（"Log out of X?", "You're all set", "What do you want to see on X?"）は太字・大きめ。本文は通常ウェイトで見出しよりかなり小さい。補助テキスト（タイムスタンプ、"Joined July 2024"、フォロワー数）はグレーでさらに小さい。3階層がはっきり視認できる。
- 絶対px値は**未確認**（目測では見出しが本文の1.5〜2倍程度）。

### 3.8 色

- **ライトモード**: 背景は純白（#FFFFFFに見える）。ローカル `490`（Settings "Your account"）で確認。
- **ダークモード（"Lights out"）**: 背景はほぼ純黒（#000000に見える）。ローカル `540`（Settings "Display"）で確認。
- X設定の「Background」選択肢は "Default"（白）と "Lights out"（黒）の2択のみが画面上に表示されており、旧Twitterにあった中間グレーの"Dim"モードのような**第3の選択肢は今回のスクショでは確認できなかった**（無いと断定はしない、未確認）。
- テキスト階層: 主テキスト黒(ライト)/白(ダーク)、副テキストはグレー、無効/プレースホルダーはさらに薄いグレー。
- アクセント色は既定=青（チェックマーク・リンク文字・選択状態・フォーカスリング）。Settings > Displayで6色から選択可（青/黄/ピンク/紫/オレンジ/緑、ローカル `540`）。
- **「Xは黒背景・白背景を基本にしている」という仮説は、ライト/ダーク両方のスクリーンショットで直接確認でき実証済み**（未確認ではなく実測レベルの確認）。

### 3.9 モーダル/ダイアログ

- 幅: 中央寄せの固定幅カード、画面幅に対して明確に余白を残す（全画面ではない）。デスクトップでは常に中央モーダルとして表示（ローカル `5, 20, 45, 90, 460, 559`、mobbin compose modal 4枚）。
- 角丸: 大きめ（四隅が丸い、目測20px前後）。
- 閉じ方: 左上"×"アイコン、またはステップ形式のフローでは左上"←"戻る矢印。オーバーレイクリックで閉じるかどうかは静止画から判定不可（**未確認**）。
- スマホでの出方（全画面かボトムシートか）: 今回のスクショ群は全てデスクトップ幅キャプチャのため、モバイル版の出方は**未確認**。
- 確認ダイアログのボタン配置は「縦積み・Primary上/Secondary下・両方フル幅」パターンが確認された（ローカル `460`）。横並びのOK/Cancelパターンは今回のスクショ内では確認できなかった。

### 3.10 フォーム

- 入力欄の構成は「ラベル→枠線付き入力欄」の2行構成が基本（ローカル `90` "Link to an X post"、`5` "Verification code"）。プレースホルダーのみの1行構成も一部混在（ローカル `240` Chatの"Message"入力、検索ボックス"Search Settings"）。
- エラー表示: 今回サンプリングした約59枚では、明確なフォームエラー状態（赤枠+エラー文言）のスクリーンショットには遭遇しなかった（**未確認**）。
- チェックボックス（Audience設定＝ローカル `440`, Content warning＝ローカル `45`）とトグルスイッチ（Push notifications, Use system setting＝ローカル `540`）の両方が混在して使われている。**使い分けの明確な基準は今回の画像だけでは特定できず、推定に留める**（本書ではOhMyCMS側の設計判断として「即時反映=スイッチ」ルールを提案）。

### 3.11 押しやすさの工夫

- **行全体クリック化**: 設定リストの各行は「アイコン+タイトル+説明文+chevron」のセットで、視覚的に行全体がクリック対象に見える設計。
- **フル幅ボタン**: モーダル内のボタンは全て横幅いっぱいに伸びるフルブリードpillボタン（ローカル `5, 20, 45, 90, 460, 559` すべてで確認）。デスクトップでもモバイル的な「押しやすさ」の作法を持ち込んでいる特徴的な点。
- アイコンボタン周囲の余白確保（ローカル `45, 90` の閉じるボタン）。
- ホバー/プレス時の視覚フィードバック（円形背景色の変化等）は一般に知られる挙動だが、静止画からの直接確認はできず**未確認**。

## 4. Directus から取るもの / X から取るもの の切り分け

原則: **「そのページ・機能が存在するか」はDirectus、「それをどう見せるか」はX。**

| 要素 | Directus由来（機能・構造） | X由来（見た目・操作感） |
|---|---|---|
| コレクション一覧 | ページの存在、名前・件数・最終更新等の情報構造 | 行の高さ、区切り線の薄さ、行末アクションアイコンの並び（★/↗/🗑）、ページネーション表記（`1-1 of 1`+前後矢印）＝ローカル `290` Hiringテーブル参考 |
| ロール&パーミッション管理 | ページの存在、権限の粒度設計 | チェックボックス/トグルの使い分け、行全体クリック化＝Settings画面群 |
| フィールド編集（スキーマビルダー） | モーダルの存在（GUIでスキーマを組む機能） | モーダルの角丸・オーバーレイの濃さ・フルブリードの保存ボタン |
| 削除確認ダイアログ | ワークフローとしての存在（誤操作防止） | ボタンレイアウト（Primary黒ボタンを上・Cancelを下に縦積み、フル幅）＝ローカル `460` |
| グローバル検索 | 検索対象の設計（コレクション横断検索など） | 結果タブ切り替えの見た目（下線インジケータ）＝mobbin Notifications `All/Mentions` |
| 通知・アクティビティログ | 何を通知するかの設計（Directus Activity機能） | バッジの見た目（青丸+白数字）、リストの行構成＝ローカル `140` |
| ダッシュボード/Insights | ウィジェットの種類・データ構造 | カードの区切り方（フラット vs カード型）＝観察§5 |
| ユーザー設定画面 | 設定項目そのものの一覧（アカウント/セキュリティ/通知等） | 3ペイン構成（ナビ／設定リスト／詳細）、行の情報密度＝mobbin Settings 6枚 |

**具体例（背景と狙いに明記された例の展開）**:
- 「コレクション一覧というページの存在」＝Directus由来。「その一覧の行の見せ方（タイトルの太字リンク＋グレー補助行＋右端アイコン群）」＝X由来（ローカル `290`）。
- 「フィールドに"必須"チェックを付けられる」という機能＝Directus由来。「そのチェックボックスが行全体クリックで反応する」＝X由来（ローカル `440`）。

## 5. 未確認事項

1. 3カラムレイアウトの各カラムの絶対最大幅(px)。目視の相対比較のみで、DevTools計測は未実施。

5. アイコンボタンの当たり判定の絶対px値（見た目より大きいという仮説の方向性は状況証拠止まり）。
6. ホバー/プレス時の視覚フィードバック（円形背景色変化等）の詳細。
7. 明確なフォームエラー状態（赤枠+エラー文言）の実例。
8. チェックボックスとトグルスイッチの使い分けの明確な基準。
9. ダークモードに「Dim」のような中間グレーの第3背景オプションが存在するか。
10. モーダルのモバイル版の出方（全画面かボトムシートか）。
11. 余白（間隔）が4px刻みか8px刻みかの実測による判定。
12. Mobbinの`search_flows`/`search_sections`は本調査では未使用（`search_screens`のみで十分な材料が得られたため）。
