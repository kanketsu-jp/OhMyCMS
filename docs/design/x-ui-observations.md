# X の実物観察 — Mobbin で引いた画面と、そこから決めた値

> 2026-08-13 / 観察者: ペイン base（トラック C）
> 由来: 堀池「**UI がまだまだです。Mobbin の MCP をつかって X の UI を勉強できている？
> 作成のボタンの大きさも全然だめです。**」
>
> 🚨 **この文書は「静止画の観察」に基づく。** DevTools で実測した px ではない。
> 画像上の比率と、既知のビューポート幅から換算した**推定値**であることを明記する。
> 「見ずに決めた値」は1つも無い。すべて下記の画面を実際に開いて観察している。

## 0. 観察方法と精度の限界（先に書く）

- Mobbin MCP の `search_screens` で X の画面を取得し、**返ってきた画像を目視**した
- 画像は幅 768px（web）/ 299px（iOS）に縮小されている。実寸は**比率から換算した推定**
- したがって **±4px 程度の誤差がある**。**比率と構造の方が信頼できる**ので、
  「入力よりボタンが低い」のような**関係**を正とし、絶対値は目安として扱う
- 🚨 **絶対値をそのまま採用していない箇所は §4 に理由つきで書いた**

## 2. 観察して分かったこと（実物の記述）

### 2-1. 🚨 ボタンの幅は「文脈」で決まる — これが「大きさが全然だめ」の正体

| 文脈 | 実物 | 根拠 |
|---|---|---|
| **ページ内のフォーム** | **内容幅・右寄せ**。文字＋左右の余白だけ。全幅にしない | A・C |
| **モーダル / SP の主要操作** | **全幅**。左右いっぱい | B・D・E・F |
| **編集画面の確定** | **ヘッダ右上のテキストボタン**。フォームの下に置かない | G・I |

A では `Confirm` が入力欄の**右下に小さく**置かれている。入力欄は列いっぱいの幅なのに、
ボタンはその 1/6 程度の幅しかない。C の `Deactivate`（破壊的）も同じ幅の扱いで、**危険度で幅は変わらない**。

一方 B・D・E・F はモーダルで、`Confirm` / `Change password` / `Next` はすべて**全幅**。

→ **全幅の大きいボタンは、X ではモーダルと SP の中だけ。** ページに直接置いたフォームの確定は小さく右寄せ。

### 2-2. ボタンは入力より**低い**

A で `Confirm` の高さは、その上の入力欄より**明確に低い**。同じ高さで並べていない。

画像上の比率（A・画像幅 768px、実ビューポート約 1280px と仮定して換算）:

| 部品 | 画像上 | 換算（推定） |
|---|---|---|
| 入力欄の高さ | 約 32px | **約 53px** |
| Confirm の高さ | 約 18px | **約 30px** |

→ **ボタンは入力の 6 割程度の高さ。** 入力＝内容を受ける器なので背が高く、ボタン＝操作なので小さい。

B のモーダル内ボタンは画像上 27px → 換算 **約 45px**。**同じ「ボタン」でも文脈で高さが違う**。

### 2-3. 入力は「ボーダー1本」か「塗り」のどちらか。両方やらない

- **web（A・B・D）**: 薄いボーダー1本。**ラベルが枠の中**（floating label）。
  枠の外に別行のラベルを置いていない。角丸は小さい（約 4px。pill ではない）
- **iOS（H）**: **ボーダー無し・背景色のみ**の塗りブロック。角丸は大きめ（約 12px）
- E（未入力）では、ラベルが枠の中で**プレースホルダの位置**にあり、
  D（入力済み）では**上に小さく上がっている**。これが floating label

→ 堀池さんの「Input のボーダーを消して背景色を bg-zinc-100 に」は **X が実際にやっていること**（H）。
  推測ではなく実物がそうなっている。

### 2-4. 無効状態は**色で**示す

- E（未入力）: `Change password` が**グレー塗り**
- D（入力済み）: 同じボタンが**黒塗り**
- I（iOS・未入力）: `Save` が**グレー文字**、G（入力済み）では**濃い文字**

→ **opacity で薄くするのではなく、色そのものを変える。**

### 2-5. 面を作らない（surface-rules.md の裏付け）

G の Edit profile は `Name / Sam Lee`・`Bio / Ordinary guy` が**行として並ぶだけ**。
**罫線で囲まれた箱が無い。** グループの区切りは**間隔と Divider だけ**。

→ `knowledge/decisions/no-nested-surfaces.md` §4 の記述（リストを罫線で囲まず行間の Divider だけ）を**実物で確認**した。

## 3. 決めた値

| トークン | 値 | 根拠 | X の実測（推定） |
|---|---|---|---|
| ボタン高さ・ページ内 | **32px**（`h-8`） | 2-2 | 約 30px → **ほぼそのまま採用** |
| ボタン高さ・モーダル/SP | **44px**（`h-11`） | 2-2 | 約 45px → **ほぼそのまま採用** |
| ボタン幅・ページ内 | **内容幅・右寄せ**（`w-fit ml-auto`） | 2-1 | 同左 |
| ボタン幅・モーダル/SP | **全幅**（`w-full`） | 2-1 | 同左 |
| ボタン角丸 | **pill**（`rounded-full`） | A〜F 全て | 同左 |
| 入力高さ | **40px**（`h-10`） | 2-2 | 約 53px → 🚨 **下げた（§4-1）** |
| 入力角丸・枠線あり | **4px**（`rounded`） | 2-3 web | 同左 |
| 入力角丸・塗り | **12px**（`rounded-xl`） | 2-3 iOS | 同左 |
| 入力の境界 | **枠線1本 or 塗り。両方やらない** | 2-3 | 同左 |
| 無効の示し方 | **色を変える**（グレー塗り／グレー文字） | 2-4 | 同左 |

## 4. X と変えた点と、その理由

### 4-1. 入力の高さを 53px → **40px** に下げた

X の設定画面の入力は約 53px と背が高い。これは **floating label（ラベルが枠の中に入る）**ため、
ラベルの行ぶんの高さが要るから。

**OhMyCMS の管理画面は floating label を採用していない**（ラベルは枠の外にある）。
枠の中にラベルが無いので、同じ 53px にすると**中身に対して枠が大きすぎる**。

→ **40px にする。** ただし **§2-2 の関係（ボタン < 入力）は守る**:
  ページ内ボタン 32px < 入力 40px。

🚨 **floating label 自体を採用するかは、この F6 では決めない。**
   採用するなら入力の高さは 53px 側に戻すべきで、それは別の判断（ラベルの置き場の変更）を伴う。
   **今回は「境界の出し方」と「ボタンの寸法」までにとどめる。**

### 4-2. 採用しなかったもの

- **ヘッダ右上に確定ボタンを置く形（G・I）** … 管理画面の各ページはヘッダを共有しており、
  ページごとに確定ボタンをヘッダへ出す構造になっていない。**F6 の範囲では見送る**。
  採用するならレイアウトの変更を伴うので、司令塔の判断が要る。

---

## 5. 未検証（正直に書く）

- **px は DevTools 実測ではない。** 画像比率からの換算（§0）。誤差 ±4px 程度
- ビューポート幅を web = 1280px、iOS = 393px と**仮定**して換算した。Mobbin は撮影幅を明示していない
- **色の16進値は読み取っていない。** 「黒／グレー／青／赤」という**関係**だけを採った
- ホバー・フォーカスの状態は静止画では見えないため**未観察**

## 8. 確認できたこと（司令塔の要約どおり）

- **セクションはカードで囲まない。** 見出し（太字・左寄せ）と余白だけで階層を作る（J・N）
- **行にボーダーが無い。** 右端の `>` で押せることを示す（J・N）
- **破壊的操作は赤い文字だけ。** ボタンの形を与えない（J の `Sign out`）
- **補足情報は最下部に小さいグレー**（J の `App Version: 12.42.15 (12420007), production` / `User ID: …`）
- **確認ダイアログ**: 主要 = 全幅 pill・青塗り / 取消 = **全幅 pill・薄いグレー塗り・ボーダー無し**（K）

## 9. 🚨 司令塔の要約に無かった発見（3つ）

### 9-1. **Divider すら無い**

X は行と行の間に Divider を引くが、**Coinbase の設定は Divider を1本も引いていない**（J・L・N）。
区切りは **余白と見出しだけ**。

→ 「面をやめて Divider にする」の**さらに先**がある。
   **設定画面では Divider も置かない**方が手本に近い。
   （一覧＝X の密度が要る場面では Divider を使う、という使い分けになる）

### 9-2. 無効状態は「**薄い塗り + グレーの文字**」

M の `Push (required)` などは、トグルが**薄い青**、ラベルが**グレー**になっている。
X の「無効はグレー、有効は黒」（§2-4）と**同じ考え方**で、
🚨 **opacity で全体を薄くするのではなく、要素ごとに色を変えている。**

### 9-3. 行は**2行**になれる（タイトル + グレーの補足）

O の通知設定は
```
✓ Security alerts            >
  via Push, Email, SMS, In-app     ← グレーの補足行
```
の形。**1行に詰め込まず、補足を下の行に落とす**。
チェック（済み）は行の**左端**、遷移の `>` は**右端**。

→ 管理画面の一覧でも、`policy / read` のような二次情報は
   **同じ行に詰めず下の行へ落とす**方が手本に近い。

### 9-4. 塗りブロックはあるが、**ボーダーは無い**（M の Preview）

M の `Preview` セクションには薄い青灰色の塗りブロックがあるが、**ボーダーを持たない**。
→ `knowledge/decisions/no-nested-surfaces.md` §2-1「罫線・背景・影のうち**1つだけ**」の実例。

## 10. 設定画面へ落とすときの形

```
設定                                    ← ページ見出し
                                        （余白）
表示                                    ← セクション見出し（太字）
  言語                          >       ← 行。ボーダーなし
  テーマ                        >
                                        （余白でセクションを分ける）
セキュリティ
  二段階認証                    ○—
  セッションの有効期限          >

サインアウト                            ← 赤い文字だけ

バージョン 0.9.0 / ユーザーID …          ← 最下部・小さいグレー
```

**カードを剥がすだけでなく、見出し + 余白 + 行の形にする**こと（司令塔の指示）。

- 行の高さ・セクション間の余白の**絶対値は測っていない**。比率と構造のみ
- 色の16進値は読み取っていない
