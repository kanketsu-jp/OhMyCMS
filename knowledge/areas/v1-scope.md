## 1. 🚨 一覧はここに写さない

**`run.mjs` が持っているもの**（**id / 題名 / 実行の順 / どの検査を呼ぶか**）は、**ここに書かない**。
写した瞬間に「2 箇所目」が生まれ、**片方が腐る**（`run.mjs` 自身がそう書いている）。

**題名や順序が要るときは、正本を引くこと:**

```
sed -n '/const V1_CHECKS/,/\];/p' acceptance/run.mjs
```

🚨 **状態・担当の表も、ここには置かない**（2026-08-17 に削除）。

置いていた頃の形は `git show 39a9ad4:knowledge/areas/v1-scope.md` で読める。
**id ごとに「状態 / 担当 / 止まっている理由」を書いていたが、そこも 2 箇所目だった**:

```
状態 … 正本は **受入を走らせた結果**（`acceptance/run.mjs`）。ここに書くと、走らせた人が
       ここも直さない限り腐る。実際 5 本とも ❓ のまま動かなかった
担当 … 正本は **各 check ファイルの冒頭**。担当が変わってもここは追随しない
```

🚨 **「写さない」を id だけに緩めても、写しは写しだった。** 残すのは §2 以降の
**読み方（どう引くか・何と混ぜないか）**だけにする。

- 🚨 **担当を知りたいときは、各 check ファイルの冒頭を読む**（そこが正本）。
- 🚨 **1 ファイル＝1 約束ではない**（同じファイルに 2 つ同居している組が在る）。**id で数えること**。

## 2. 🚨 状態を知りたいときは、走らせるしかない

**この文書は状態を持ちません**（**持っていた頃、5 本とも ❓ のまま動きませんでした**）。

```
🚨 **「実装が在る」と「受入が緑」は別**。緑かどうかを言えるのは、走らせた結果だけ
🚨 **「回した」と「いま緑」も別**。申告は状態ではない（走らせた時点の木は、もう動いている）
🚨 **SKIP は緑ではない**。`v1-cd-editor-otp.mjs` の冒頭に
   「**実装より先に基準を書いている。未実装なら SKIP（PASS にも FAIL にもしない）**」と在る
   ＝ **「まだ作っていない」と「通った」を分けること**
```

🚨 **読んで埋めないこと。** 走らせて、**その報告に sha と叩き方を添えること**。
