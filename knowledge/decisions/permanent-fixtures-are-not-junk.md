# 検証用に見えるデータを、名乗りが無いという理由で消さない

> 由来: 2026-08-15。共有 DB に検証用に見えるコレクションが見え、
> 「**全員に持ち主を聞き、名乗りが無ければ消す**」という手順で片付けようとした。
>
> 🚨 **【同日中に訂正】発端の報告そのものが 2 か所で間違っていた**（決定は変わらない。§0 を参照）。
> そのうち `zz_probe_act`（= `zz_probe_actions`）は
> [checks-must-declare-blind-spots](./checks-must-declare-blind-spots.md) で
> **「常設にする」と決めたもの**だった。**10 人が全員、決定文書を読まずに消しかけた。**
> 問題は「持ち主が分からない」ことではなく、**書いてあることが読まれていない**ことだった。

## 0. 🚨 発端の報告は 2 か所間違っていた（消さずに残す）

**決定は変わらない**——「**常設と決めたものを、全員が知らずに消しかけた**」は実際に起きた。
ただし**引き金になった数字は 2 つとも誤り**だったので、書き残す。
**誤りの形そのものが、この決定と同じ根を持っている。**

| 報告 | 実際 |
|---|---|
| 「**本番**に見えている」 | **開発サーバ（`:3102`）だった。** 本番は一度も開いていない |
| 「**4 件**」 | **15 件**。probe の実装が `子.slice(0, 4)` で**先頭 4 件を「例」として**出しており、**同じ出力の中に `{"件数":15}` と書いてあった** |

🚨 **例（サンプル）を母集団として数えた。** `slice` / `LIMIT` / `head` / 「例」と書かれた出力から
数を採らないこと。**本当の件数が同じ出力の中に載っていることがある**（今回まさにそれ）。
名前が 12 文字で切れていたのも同じ実装によるもの（`zz_probe_actions` → `zz_probe_act`）。

**止まったのは「どの URL で採ったか」を聞いた人が居たから。**
**数字を受け取ったら、どこで採ったかを聞く**——これが唯一効いた手だった。

## 決定

**共有 DB の行・コレクション・ファイルを消す前に、リポジトリを grep する。**

```
grep -rn "<その名前>" knowledge/ docs/ apps/studio/scripts/
```

🚨 **名乗りは「消してよい」の根拠にならない。**
**リポジトリに理由が書かれていないことを確かめて、初めて消せる。**

### なぜ名乗りでは足りないか

- **意図して常設にしたものには、担当者が居ない。** 決めた人はもうそのペインに居ないかもしれない
- **名前が「捨ててよい」に見える。** 🚨 `zz_` は「検証用＝消してよい」に読める。
  **実際には「消えると検査が再現できなくなるもの」が同じ接頭辞で並んでいる**
- **「作った」と「使った」は別。** 名乗りを所有と読むと、**他人の検証が壊れる**
  （2026-08-15、`acc_748015_pl` について 2 人が独立に「**使ったが作っていない**」と申告した。
  この区別が無ければ「誰のものでもない」と判定されて消えていた）

## 名乗るときの型

**「作った」「使った」「既定値として持っている」のどれかを書く。**
「知らない」も報告する——**全員が黙ると、消してよいのか永久に決まらない。**

**次の掃除で消える**（今回まさにそうなりかけた）。

### `zz_probe_dialog` の名乗り（2026-08-15・storage）

**使った。作ってはいない**（誰かが私のために作ってくれたものを、私が使った）。
司令塔から「使い終わったら常設にするかどうかを返せ」と言われたので、**常設にすると決めた**。

🚨 **消すと、同じ穴に戻る。しかも「違反 0 件」は出続ける。**
ダイアログの中の要素は**開くまで存在しない**ので、到達できないことと
違反が無いことが**同じ顔で出る**（この文書が生まれた事故と同じ形）。

**依存している検査**: `audit-surface-depth.mjs` を
`--paths /admin/content/zz_probe_dialog/new --click '[data-file-picker-trigger]'` で走らせる。
🚨 `--click '[data-slot=dialog-trigger]'` は使わないこと——**PC では別のダイアログを先に掴み、
この箱を開けないまま「違反なし」が出る**（SP は並びが畳まれているので、たまたま開けていた）。

## これから常設にするものの名前

**`keep_` で始める。** 名前だけで「消してはいけない」が分かる形にする。

🚨 **既にあるもの（上の表）は改名しない。** 共有 DB の DDL を伴い、
**改名の失敗のほうが、名前が分かりにくいことより高くつく**ため
（**改名の途中で落ちると、消えたのと同じ状態になる**——それがまさに避けたい事故）。
**表に載っていることが根拠**になる。

## 手当ての状況

> 🚨 この節は当初「**まだやっていないこと（unverified）**」だった。
> **同じ日に shell が検知の仕組みを入れたので、見出しごと書き換えた**
> （中身だけ直して見出しを残すと、**斜めに読む人が「未着手」と読む**）。

- **DB 側から「常設」だと分かる仕組みは無い。** いまは
  **名前（`keep_`）と、この表**の 2 つだけが手掛かり
- ✅ **常設のものが消えたことを検知する仕組みはある。** 元の事故
  （「消えて、その形の 500 が再現できない時間帯があった」）の記録は残す。
  `bun run --filter @ohmycms/studio verify:fixtures` が、上の表に載っている常設 fixture が
  DB に存在することだけを確認する。**この文書の表が SoT で、検査はこの表を読む。**
  常設 fixture を足す人はこの表に 1 行足せばよい。スクリプト側に名前を足さない。
  **実 DB が要るので pre-commit には載せない**。
  🚨 **この検査が「0 件を全部あると読む」形になっていないことを実測した**（toast・同日）:
  表の見出しをわざと壊す → **`fixture が 0 件です` / exit 2**（**沈黙して緑にならない**）。
  壊した文書は復元し、`git status` が空であることも確認した。
  **空の期待は「全部ある」ではない**——この形は今日いちばん多く踏んだ罠なので、ここに残す。

### 🚨 この守り手（`verify:fixtures`）が見ていない範囲

**守り手を名指しするだけでは足りません。** 何を見ていないかを書きます（実測・2026-08-15）。

| 見ているか | 中身 |
|---|---|
| 🟢 見る | **上の表に載っている名前が、DB に在るか**（消えたら落ちる） |
| 🔴 **見ない** | 🚨 **表に載っていない検証用データ**。実測: DB に `zz_*` / `acc_*` が **6 件**あるのに、表は **3 件**（`zz_a` / `zz_len63_xxx…` / `zz_probe_paged` が漏れている）。**消えても緑のまま** |
| 🔴 **見ない** | **中身**（行が在るか・列が在るか）。**名前のテーブルが在れば通る**ので、`zz_probe_actions` の行が全部消えても気づけない |
| 🔴 **見ない** | **表の 4 列（記録日 / 状態 / 決める人 / 何を決めるか）が埋まっているか**。**空でも通る** |

→ **「`verify:fixtures` が緑」は「表に載せた分は在る」までしか言っていません。**
🚨 **載せ忘れは、この検査では永久に見つかりません。** 載せるのは人の仕事です（§ 上の注記）。

## アンチパターン

- ❌ 「全員が『違う』と言ったから消す」
- ❌ 名前の接頭辞（`zz_` / `test_` / `tmp_`）を「捨ててよい」の根拠にする
- ❌ 名乗り＝所有と読む（「使った」人を持ち主として扱う）
- ❌ 常設にすると決めたのに、上の表に足さない
- ❌ **サンプルを母集団として数える**（`slice` / `LIMIT` / `head` / 「例」と書かれた出力から数を採る）
- ❌ 受け取った数字を、**どこで採ったかを聞かずに**次の人へ渡す
- ❌ 消す前の grep で **0 件だったことだけ**を根拠にする
  （🚨 **実在する名前で 1 件以上出ることを対照として確かめる**。
  「見ていない 0」と「無い 0」は同じ顔で出る）
