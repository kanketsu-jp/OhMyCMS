# 設定は種 1 つ。値はそこから導出し、明示が勝つ

**決定 2026-08-19（堀池）。** 起動に要る環境変数を `OHMYCMS_SEED` 1 つに寄せ、
DB のパスワード・秘密の暗号鍵・初回ログイン・掃除トークンを**そこから決定的に導出する**。
個別に環境変数を指定すれば、**そちらが勝つ**。

## なぜ

堀池の定義（原文）:
> **ゼロコンフィグを目指すというのは無駄なものやあとで設定できるものはなくても動くように
> 最小限にするということです。ちゃんと意味がある前提でミニマム化されたものは洗練されていると
> 評価します。なので、環境変数自体はあっても良くて、例えば sshkygen でハッシュを作りそれを
> いろんな場所で一位の初期化キーや暗号やサービス名として使うなどができるならいい。**

ゼロコンフィグ＝設定を 0 個にすることではない。**意味のある最小限にすること**。
環境変数は在ってよく、**1 つの種から複数の用途を導出できるなら、そのほうが洗練されている**。

## 導出の定義（両側で 1 バイトも違わないこと）

```
derive(purpose) = SHA-256( SEED + "|ohmycms|" + purpose )   ← 生バイト 32 個
```

| 用途 | purpose | 形 | 実装 |
|---|---|---|---|
| DB のパスワード | `db-password` | hex 64 文字 | `docker/db-entrypoint.sh`（shell）と `lib/db/connection-string.ts`（Node） |
| 秘密の暗号鍵 | `secret-key` | base64（32 byte ちょうど） | `lib/settings/secret-box.ts` |
| 初回ログイン | `setup-password` | base64url 先頭 20 文字 | `lib/auth/setup.ts` |
| ゴミ箱掃除 | `trash-purge-token` | base64url 43 文字 | `app/api/trash/purge/route.ts` |

土台は `apps/studio/lib/config/derive.ts`。**新しい用途を足すときは purpose を足すだけ**で、
環境変数は増えない。

## 🚨 「明示が勝つ」は、そのまま移行手段でもある

**`POSTGRES_PASSWORD` は initdb が初回にしか焼かない。**
既存のボリュームで導出値へ変えると、**本番が繋がらなくなる**。
だから既存の本番は明示指定のまま残し、**新規デプロイだけが種を使う**。

同じ理由で、外部サービスに登録済みの値も導出しない:
🚨 **`OHMYCMS_PUBLIC_URL` は導出対象にしない**（Google の戻り先 URI・SAML の Entity ID / ACS URL と
一致していなければならない。詳細は `lib/auth/urls.ts` のコメント）。

## 実測（2026-08-19）

```
種 test-seed-0123456789 に対して、3 者が完全一致:
  python（独立実装・基準）… 2ae14e33b713d8e1d4341899b0a4b7c607bf4edc1d972eb5b2c2a4985deb61fd
  Node（アプリ側）………… 4 つとも一致
  sha256sum（db コンテナ）… 一致
🟢 対照 種を 1 文字変えると 4 つとも別の値（＝ 導出は種に依存）
🟢 対照 種が無いと derive は null を返す（例外を投げない）
🟢 対照 db を 172.17.0.x 経由（trust の外）で測り、導出パスワードで認証・違う値は拒否
   🚨 127.0.0.1 は pg_hba.conf で trust なので、そこで測ると認証を通っていない
🟢 対照 種も POSTGRES_PASSWORD も無いと exit 1（変数名だけを出し、値は出さない）
🟢 対照 POSTGRES_HOST_AUTH_METHOD=trust なら止めない（逃げ道は塞いでいない）
```

## 到達点

```
本番で人が設定するもの   4 つ → **2 つ**（OHMYCMS_SEED と OHMYCMS_PUBLIC_URL）
🟢 対照 分類の合計 34 / 実在する環境変数 34（どこにも入らないもの = なし）
   種から導出 5 ／ 既に GUI で設定できる 12 ／ 固定値でよい 7 ／
   開発・ビルド専用 5 ／ 旧経路（S3_* で代替済み）4 ／ 残る 1
```

## 副作用として直ったこと

🚨 **`OHMYCMS_SECRET_KEY` は本番のコンテナに 1 度も届いていなかった**
（`compose.dokploy.yml` に渡す行が 0 件・`.env.example` にも記載が無かった）。
種から導出するので、**変数を足さずに解決した**。
