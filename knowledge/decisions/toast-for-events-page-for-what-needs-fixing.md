# 通知は「終わったこと」だけトーストへ。直す必要があるものはその場に残す

> 由来: 2026-08-15 司令塔の裁定（原文）「**出来事はトースト、状態はページに残す。
> ユーザーが対処を要するものはタイマーに載せない**」。
> 上位に堀池さんの決定「画面の中に『保存しました』を埋め込むのは廃止。トーストにする」
> 「**エラーもトーストへ**（成功だけではない）」がある。
> **この文書は「エラーもトーストへ」を否定しない。適用範囲を決めている。**

## 決定

**通知を出す場所は、次の1問で決める。**

> 🚨 **利用者は、これを読んで何かしないといけないか。**

| 答え | どこへ | 例 |
|---|---|---|
| **いいえ**（もう終わったこと） | **トースト**（3秒・右下 / SP は上部） | 保存しました・削除しました・送信しました |
| **はい**（直す必要がある） | **その場に残す** | 入力が足りない・関連コレクションが未指定・権限が無い |

## 🚨 軸は「出来事か状態か」ではない

最初は「**出来事 / 状態**」で切ろうとした。**これは間違いやすい。**
「保存に失敗した」は文法的には出来事だが、**利用者は入力を直さないといけない**ので残す。

**正しい軸は「対処が要るか」。** 3秒で消える器は、**読み終わる前に消えてよいものにしか使えない。**

## 実装での線引き（実測に基づく）

| クエリ | 扱い | 理由 |
|---|---|---|
| **`?notice=`** | **トースト**（`components/ui/query-notice-toast.tsx`） | `item_saved` / `item_deleted` など、**終わったこと**しか運ばない |
| **`?error=`** | **ページの `ErrorBanner` に残す** | 運ぶのは `error_invalid_input` / `error_field_required` / `error_related_collection_required` / `error_delete_target_required` / `error_invalid_kind` と `apiMessage()`（403 含む）。**全部が入力のやり直しを要する** |

🚨 **`?error=` は一度トーストへ移して、戻している。** 同じ書き換えを繰り返さないこと。

- `?notice=` は**出したら URL から消すところまでが1組**。消さないと戻る操作のたびに
  「保存しました」が出続ける（保存していないのに）
- 🚨 **`?error=` は URL から消さない**（ページ側がまだ描いているため）
- 🚨 **`i18n/notice.ts` の許可リストを捨てない。** URL は利用者が自由に書けるので、
  でたらめなキーが素通りすると**未定義キーがそのまま画面に出る**。
  出す場所がページからトーストへ変わっても、この検査の意味は変わらない

## 消してはいけないもの

- **二重送信の防止**（`useSubmitOnce` / ボタンの `disabled` / スピナー）
  → 堀池さん「二重クリック防止のスピナーなどは必要。これはボタンの Variant」
- 🚨 **進行の表示**（`*_uploading` / プログレス）。**出来事でも状態でもない。**
  「操作そのものが見えている」もので、**3秒で消える器では表現できない**
  （トーストにすると、アップロードがまだ続いているのに消える）
- **フォームの検証メッセージ**（`aria-invalid` と対のもの）。**その欄の隣**に出す

## 🚨 なぜこの文書があるか（決定がコードのコメントにしか無かった）

2026-08-15、design が **`docs/design/pending-errorbanner-split.md`** を書いて
「`?error=` をトーストへ移すべきか、堀池さんの裁定を待っている」と報告した。
**裁定はすでに出ており、しかも一度移して戻した後だった。**

見落とした理由は単純で、**決定が `query-notice-toast.tsx` の JSDoc コメントにしか無かった**。
`knowledge/decisions/` を探しても出てこないので、「まだ決まっていない」と読んだ。

- 🚨 **「判断待ち」と書く前に、既に決まっていないか探す。**
  `grep -rl "<決定の言葉>" knowledge docs apps` を1回走らせるだけで防げた
- 🚨 **決定をコードのコメントだけに置かない。** 触っているファイルを開いた人にしか届かない。
  コメントは「なぜこの実装なのか」を書く場所で、**決定の正本は `knowledge/decisions/`**
  （`AGENTS.md` §8）。コメントからはここへリンクする
- **一度戻した経緯は、必ず残す。** 残さないと、次の人が同じ書き換えを「改善」として提案する
  （実際にされた）
