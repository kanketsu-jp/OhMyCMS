# 範囲違いで画面を増やさない／1 件のページは「出すものが在るか」で決める

> 由来: 2026-08-17。堀池指示「**directus を見習い、UIUX やページの構成。下層ページも真似する**」を受けて
> 司令塔が構成を数え、**`reports/manage` という 4 つ目**と、**1 件のページが無い 2 領域**を design へ回した。
> 🚨 司令塔は「**どちらでもよい。決めて、理由を残してください**」「**画面を見てから決めて**」と書いた。
> 関連: [[list-views-are-switchable-layouts]]（表示形式の切り替え）／[[every-element-must-earn-its-place]]

## 0. 決めたこと

1. **同じ対象の「範囲違い」で画面を増やさない。** 同じ一覧の**切り替え**にする。
2. **1 件のページを作るかは「3 層に揃える」ではなく「そのページに出すものが在るか」で決める。**

## 1. 🚨 画面を見て決めた（ソースだけでは決められなかった）

司令塔は「ソースしか読んでいない」と書いた。**画面を並べたら、ソースからは見えないことが出た。**

```
🔴【測った】:3102 で 2 つを並べた（2026-08-17・design）
  /admin/reports        パンくず「不具合の報告」／タブ **未解決・解決済み**／「未解決の報告はありません。」
                        右上に「報告する」
  /admin/reports/manage パンくず「報告管理」  ／タブ **未解決・解決済み**／**同じ空の文言**
                        🚨 右上のボタンが無い
＝ 🚨 **見た目がほぼ同一。違うのはパンくずの語と、右上のボタンの有無だけ**
```

🚨 **そして、いちばん効いたのはここ:**

> **利用者は「自分の報告を見ているのか、全員の報告を見ているのか」を、画面から知る手段が無い。**

タブは**両方とも「未解決／解決済み」**で、**範囲を示すものがどこにも無い**。
分かるのは**パンくずの語だけ**（「不具合の報告」か「報告管理」か）——
🚨 **語が違うだけで、同じ顔の画面が 2 つある**状態だった。

## 2. だから畳む（＝ 範囲をタブにする）

```
✅ `/admin/reports` に **範囲の切り替え**を置く（自分 / 全員）
   API は既に対応している … `GET /api/reports?scope=all`（`manage` が使っている）
   🚨 権限が無ければ 403 なので、**出す・出さないは既に決められる**
🚫 `/admin/reports/manage` は残さない
```

🚨 **Directus に揃えるためではない。** Directus が同じ collection の preset で出すのは知っているが、
**採る理由は上の実測**——**畳めば「いまどちらを見ているか」が常に画面に出る**から。
（[[list-views-are-switchable-layouts]] §5「見た目を Directus に似せるのではない」と同じ立場）

🚨 **まだ実装していない。** この決定は「そうする」までで、**畳む作業は別**。

## 3. 1 件のページは「出すものが在るか」で決める

```
🔴【測った】/admin/labels の画面（:3102・2026-08-17）
   「いまあるラベル」… **名前 ＋ 色のアイコン**が 3 件（それだけ）
   「システムのラベルは削除できません（名前と色は変えられます）」
   「ラベルを作る」… 名前 ／ 色 ／ 作る
＝ 🚨 **1 件のページに置くものが無い**（名前と色は一覧でそのまま見えていて、その場で直せる）
```

**唯一「1 件のページなら出せそう」なのは「このラベルが付いたファイル」だが、
それは既にファイル一覧の絞り込みで出せる**（`/admin/files?label=…`。画面に
「〜で絞り込み中／絞り込みを解除」が出る）。＝ **§2 と同じ形（範囲違いは一覧の切り替え）**。

✅ **`labels` に 1 件のページは作らない。**
🚨 **3 層（一覧 / 1 件 / 新規）に揃えること自体は目的ではない。**
   揃えるのは「**画面の種類を増やさない**」ためであって、**空のページを足すためではない**。

## 4. 判断のしかた（次に同じ問いが来たとき）

```
Q1. 「別の画面」に見えるものは、**同じ対象の範囲違い**か？
    → はい … 🚨 **一覧の切り替えにする**（画面を増やさない）
      ✅ そのとき **範囲が画面に出ていること**を必ず確かめる
        （**出ていないなら、畳んでも「どちらを見ているか分からない」は直らない**）
    → いいえ（対象が違う）… 別の画面でよい

Q2. 1 件のページを作るか？
    → **そのページにしか置けないものを 1 つ挙げられるか**で決める
      挙げられない … **作らない**（[[every-element-must-earn-its-place]]）
      挙げられる …… 作る。🚨 **司令塔の手本**: 編集を付けない／できないことをその場に書く／
        空を空白で出さない／必ず在るものを見出しにする／1 件だからと列を増やさない
```

## 5. やらないこと

- ❌ 「Directus がそうしているから」を理由にする（**理由は自分たちの実測**）
- ❌ 3 層に揃えるために、出すものが無い 1 件のページを作る
- ❌ 範囲違いを別画面にして、**範囲を画面に出さない**（今回の `reports` がその形だった）

## 6. レビュー観点

- [ ] 新しい画面を足すとき、それは「別の対象」か「同じ対象の範囲違い」かを言えるか
- [ ] 範囲違いを一覧に畳んだとき、**範囲が画面に出ているか**（タブ・絞り込みの表示）
- [ ] 1 件のページを作るとき、**そこにしか置けないもの**を 1 つ挙げられるか
- [ ] 🚨 判断の前に**画面を見たか**（ソースだけで決めていないか。今回それで結論が変わった）
