# ポートは 31xx 帯に寄せ、よく使うポートを避ける

## 背景

> 堀池（2026-08-13）: 「**OhMyCMS はよく使うポートを避けます。なので、3101 など
> なにかルールを作って。**」

**3000 は Next.js の既定**なので、開発機で他のプロジェクトを同時に動かすと必ず取り合う。
実際に踏んだ:

- 受入ハーネスと本番スタックが同じポートを掴んで、ハーネスが誤って FAIL した
  （→ `DOCKER_PORT` を 3998 に分離して回避したが、**その場しのぎだった**）
- 管理画面が全ページ 500 になる事故。原因は `requestOrigin()` が host ヘッダから
  自分の URL を組み立てるため、**公開ポート ≠ コンテナ内ポート**だと壊れる

🚨 **後者が効く。** 「衝突したら別のポートに逃がす」を場当たりでやると、
**公開ポートとコンテナ内ポートがずれて、原因の分かりにくい 500 を生む。**

## 決定

> 基準日: 2026-08-13

**OhMyCMS が待ち受けるポートは 31xx 帯に固定する。用途ごとに番号を決め打ちする。**

| 用途 | ポート | 環境変数 |
|---|---|---|
| **Studio（本番 / Docker）** | **3101** | `STUDIO_PORT` |
| **Studio（開発 / `bun run dev`）** | **3102** | — |
| **受入ハーネス / studio-acc**（開発ビルド） | **3103** | `DEV_PORT` |
| **Storybook** | **3104** | — |
| **受入ハーネスが立てる本番スタック** | **3105** | `DOCKER_PORT` |
| **MinIO（S3 互換・V1-B の検証用）** | **3106**（API） | `MINIO_PORT` |
| **MinIO のコンソール** | **3107** | `MINIO_CONSOLE_PORT` |
| **Keycloak（SAML のテスト IdP・V1-A の検証用）** | **3108** | — |
| **MailHog の受信箱（OTP の送信経路・V1-D の検証用）** | **3109** | — |
| **worktree の開発サーバ（1 本目）** | **3110** | —（下記のとおり引数で渡す） |
| **worktree の開発サーバ（2 本目以降）** | **3111 / 3112 …** | — |
| PostgreSQL | **5436**（既存を維持） | `DB_PORT` |

**3113 以降は将来のプロセス用に空けておく**（Hono へ API を分離したときなど）。

🚨 **3110〜3112 が要る理由**（2026-08-15 に決定・堀池さん判断）:
ペインが**隔離 worktree で作業するようになった**（共有ツリーだと、他ペインの
書きかけが混ざって「自分のツリーでは緑・HEAD では赤」が見えなくなるため）。
worktree の開発サーバは **:3102 とは別のコードを出す**ので、同じポートには置けない。
**空いているポートへ場当たりで逃がすのを禁じている以上、番号を先に決めておく**のが筋。
🚨 **`PORT=3110 bun run dev` は効かない。** `apps/studio/package.json` の dev は
`next dev --port 3102` と**番号を直書き**しているので、環境変数は無視される
（実際にこれで起動したつもりが :3102 を掴みに行き、`EADDRINUSE` で落ちた。2026-08-15）。
**正しい起動**（`apps/studio` で）:

```
bunx next dev --port 3110
```

**終わったら止める**（掴んだままにすると次の人が困る）。

🚨 **3106 / 3107 / 3108 / 3109 は「検証のときだけ立てるもの」**で、出荷物には含まれない。
それでも表に載せるのは、**載せないと衝突するから**。実際に一度踏んだ:
受入担当が SAML のテスト IdP に **:3107 を提案しかけた**が、**MinIO のコンソールが
既に取っていた**（storage の実測で判明・2026-08-13）。→ :3108 へ変更、司令塔が承認。
**「空いているはず」で決めない。必ずこの表と実測で確かめる。**

🚨 **ハーネスは2つのアプリを立てる**（受入担当の指摘で判明）。当初この表は 3103 の1つしか
書いておらず、`DOCKER_PORT` と `DEV_PORT` が**どちらも 3103 になって衝突**していた。

- `DEV_PORT` = `studio-acc`（**開発ビルド**。dev-login が生きているのでセッションを作れる）
- `DOCKER_PORT` = `--docker` で立てる**本番スタック**（基準 #1 #2 の判定に使う）

**この2つは同時に立つので、必ず別の番号にする。** ハーネス側に衝突を検出して落とす検査も入っている。

### 避ける番号（使わない）

`3000`（Next.js 既定）/ `3001` / `5432`（Postgres 既定）/ `8080` / `8000` / `5173`（Vite）/ `6006`（Storybook 既定）

## 理由

**「空いているポートを探す」のではなく「最初から衝突しない帯に置く」。**
探す方式は、探した時点では空いていても**次に別のプロジェクトを起動すると取られる**。

31xx 帯を選んだのは、**主要なツールの既定値が入っていない**ため
（3000 番台の先頭は Next.js / Rails などが使うが、3100 以降はほぼ空いている）。

## 🚨 訂正（2026-08-13・同日中に反転）

**この決定の初版は「コンテナ内のポートは変えない（3000 のまま）」と書いていた。これは誤りだった。**

初版の文は、**同じ段落の中で原因と結論が逆になっていた**（ui 担当の指摘）:

- 説明: 「**公開ポート ≠ コンテナ内ポート** だと `requestOrigin()` が壊れて全ページ 500」← 正しい
- 指示: 「だからコンテナ内は 3000 のままにする」← **これが `3101:3000` という「≠」を作っていた**

### 実測（司令塔が確認）

```
curl :3101/api/health  → 200      ← API は通る
curl :3101/login       → 200      ← 内部 fetch をしない画面は通る
curl :3101/admin       → 500      ← 🚨 内部 fetch をする画面が落ちる
```

ui 担当の比較実験（同じコード・ポートの対応だけ変えた）:

| 対応 | 結果 |
|---|---|
| `3999:3000`（ズレ） | `/admin` `collections` `files` `folders` `settings/users` `settings/roles` が**全部 500** |
| `3999:3999`（一致） | 同じ6枚が**全部 200**。ログ: `connect ECONNREFUSED 127.0.0.1:3999` |

**機構**: ブラウザが `Host: localhost:3101` で来る → `requestOrigin()` が `http://localhost:3101` を返す
→ **コンテナが自分の 3101 へ fetch** → コンテナ内で待っているのは 3000 → ECONNREFUSED → 500。

🚨 **`curl` で API を叩くと 200 なので気づけない。落ちるのは画面だけ。**

### 正しい指示

**公開ポートとコンテナ内ポートを一致させる。**

```yaml
ports:
  - "${STUDIO_PORT:-3101}:${STUDIO_PORT:-3101}"
x-app-env:
  PORT: ${STUDIO_PORT:-3101}      # Dockerfile の PORT=3000 を上書きする
```

Dockerfile は変えなくてよい。`acceptance/compose.acceptance.yml` は既に `3103:3103`（一致）になっており、
**ハーネス側は一致・本番側はズレ**という食い違った状態だった。

### 本命の対処（別途）

`requestOrigin()` が**自分自身を呼ぶときにホストヘッダを使っている**のが根本原因。
サーバ内部からの呼び出しは、ホストヘッダでなく**自分が待ち受けているポート**を使うべき。
上のポート一致は**それまでの回避策**。

## 影響

- **公開ポートとコンテナ内ポートを一致させる**（上記の訂正どおり）
- `.env.example` の `STUDIO_PORT` を 3101 にする。`.env` を持っている人は各自で直す
- `acceptance/run.mjs` の `DOCKER_PORT` を 3103 にする
- README / AGENTS.md §5 のコマンドインデックスの URL を書き換える
- 🚨 **ハーネスと本番スタックのポートが別であること自体は維持する。**
  同じにすると[[shared-resources-are-exclusive]]の事故が復活する

## 教訓

**ポートは「共有資源」の一種。** 早い者勝ちで取ると、後から来たプロセスが黙って壊れる。
資源は**先に割り当てを決めてから使う**。
