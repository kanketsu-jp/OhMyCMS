# 関連は右パネルで開く（ページを離れない）。ただし関連の欄はまだ無い

> 由来: 2026-08-17。堀池指示「**全て directus を見習う**」を受けて base2 が Directus を読み、
> 11・12 便目で 2 つ報告した: ①**戻る導線の順番が逆**（Directus は「そもそも離れない」が先で、
> 「離れたら履歴で戻る」は後）②**右パネルは 21 本の道具箱で、既定で開き、幅と開閉を端末に記憶する**。
> 司令塔が「**判断が要ります**」と design へ回した。
> 関連: [[every-element-must-earn-its-place]] ／ [[no-nested-surfaces]] ／ [[ui-placement-by-frequency]]

## 0. 🚨 まず、問いの形が違っていた

**【測った】この PJ には「関連の欄」がまだ無い。**

```
components/admin/item-form.tsx（項目の編集フォーム・260 行）
  `field.type` …… 9 件（uuid / string / dateTime / integer … で入力を選び分けている）
  🚨 `relation` … **0 件**   🚨 `foreign` … **0 件**
🟢 対照 同じファイルで存在しない語を数える … 0 件（＝ 数え方は動いている）

app/(admin)/admin/content/** で `relations` … **0 件**
🟢 対照 同じ範囲で `fields` … 23 件

紛らわしいもの: `components/admin/relation-form.tsx` は**スキーマ側**
  （コレクション間の関連を**定義する**フォーム）で、**項目の欄ではない**。
  使っているのは `admin/collections/[collection]` の 1 画面だけ。
`lib/items/relations.ts`（141 行）は在るが、**権限の境界を判定するため**のもの
  （[[relation-permission-boundary]]）。**画面に関連を出すためではない**。
```

🚨 **つまり「関連を辿るとページを離れてしまう」という不具合は、まだ起きていない。**
外部キーの列は **uuid の文字入力**として出ている。

→ だからこの決定は **「いま在る画面を直す」ではなく「これから作るときの決まり」**。
🚨 **決まりを先に置く理由**: 関連の欄は「作ってから直す」と**作り直しになる**
（ページ遷移を前提に組むと、右パネルへ移すときに保存の経路ごと変わる）。

## 1. 決めたこと

### 1-1. 関連を辿るとき、既定でページを離れない

**関連の欄から相手のレコードを開くときは、右パネルに積む（`push`）。ページ遷移にしない。**

- 戻るのは `pop`（**右パネルが既に持っている**）
- 🚨 **リンクは残す**（新しいタブで開く・キーボードで辿る、が消えるため。
  `files-table` で行のクリックを足したときと同じ判断）
- 🚨 **「履歴で戻る」を先に作らない。** base2 の指摘どおり**順番が逆**で、
  **離れる回数が減らないまま戻る道だけ増える**

### 1-2. 右パネルの「積み重ね」は、Directus の形に作り替えない

**【引いた】いまの右パネルは既に「積み重ね（stack / push / pop）」を持っている**
（`right-panel.tsx`。深さ 1 = そのページの説明、押し込むと不具合報告などが上に載る）。

🚨 これは**堀池が名指しで指定した形**（2026-08-15 原文）:
> 「PCの場合は右サイドバーに表示させます。よって、**右サイドバーは内容が切り替わる設計が必要**。
>  ただし報告した後は**戻るボタンで一つ前の表示に戻る**。」

Directus の右パネルは **21 本の「詳細」が同時に並ぶ道具箱**（アコーディオン型）で、**別物**。
✅ **こちらの「切り替わる／戻る」型を維持する。** 見た目を似せるために作り替えない
（[[list-views-are-switchable-layouts]] §5 と同じ立場——**似せることが目的ではない**）。

### 1-3. 「既定で開く」は、いまは採らない

```
Directus が既定で開くのは、**中身が毎回使うもの**（書き出し・取り込み・コメント・並びの設定）だから
いまのこの PJ の深さ 1 は **「このページの説明」**（`page-info-panel`）
   ＝ 🚨 **毎回は要らない**。常に開くと、横幅をそのぶん恒久的に払うことになる
   （[[every-element-must-earn-its-place]]「常設には理由が要る」）
```

✅ **関連が右パネルに入って、はじめて「毎回使う」側になる。そのとき再判断する。**
🚨 **そして、この 1 点は堀池の判断**（司令塔に「右パネルを既定で開くか」を板へ載せてもらっている）。
🚨 **狭い画面では「既定で開く」を採らない**——本体が潰れる。採るとしても**幅で分ける**。

### 1-4. 幅を変えられるようにはしない（いまは）

誰も困っていない。**開閉を覚えるほうが先**で、それも 1-3 が決まってから。
🚨 **3 点セットは「まとめて採る」ものではない**——**1 つずつ理由が要る**。

## 2. Directus と違えるところ（理由つき）

| | Directus | ここ | なぜ |
|---|---|---|---|
| 関連を辿る | 離れない（`enableLink` 既定 false） | **同じにする** | 離れると、書きかけが飛ぶ・戻り方が要る |
| 右パネルの構造 | 21 本が並ぶ道具箱 | **切り替わる／戻る型を維持** | 🚨 堀池が名指しで指定した形 |
| 既定で開く | 開く | **開かない（いまは）** | 中身が「説明」だけで、毎回は要らない |
| 幅を記憶 | する | **しない（いまは）** | 困っている人がいない |

## 3. やらないこと

- ❌ 関連の欄を作る前に「履歴で戻る」だけ入れる（**順番が逆**）
- ❌ 右パネルをアコーディオン型へ作り替える（**堀池の指定を上書きしない**）
- ❌ 3 点セットをまとめて採る（**1 つずつ理由を出す**）
- ❌ 「Directus がそうしているから」を理由にする（**理由は自分たちの実測と制約**）
- ❌ 関連の欄から**ページ遷移で**相手を開く実装を足す（この決定に反する）

## 4. レビュー観点

- [ ] 関連の欄を作るとき、相手を**右パネルに積んで**いるか（遷移していないか）
- [ ] リンク（新しいタブ・キーボード）を消していないか
- [ ] 右パネルへ何かを足すとき、**深さ 1 を押しのけていないか**（`push` で載せているか）
- [ ] 「既定で開く」を入れるなら、**狭い画面で本体が潰れないか**を実測したか
- [ ] 3 点セットのうち採るものについて、**それぞれ理由を書いたか**
