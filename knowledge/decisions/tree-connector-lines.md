# ツリーの接続線は「肘」と「通し線」を分けて描く

> 由来: 2026-08-15。堀池さんが「角丸の罫線」の実物（YouTube のコメント欄）と、その DOM / CSS を提示された。
> 原文: 「**角丸の罫線と言っているのはこれのこと**」
> 🚨 **この規約は OhMyCMS のもの。外部のどこかに従っているのではない。**
> 当初、司令塔から「direct.kmdr.app のルールに OhMyCMS が従う」という前提が示されたが、
> **2026-08-15 に取り下げられた**。堀池さん原文:
> 「**ツリー構造について Direct.kmdr.app を参考にするとは一つも言っていない。**」
> 「見習え」と言われたのは**サイドバー**についてで、罫線については言われていない。

## TL;DR

- **肘（曲がり）と通し線（縦線）は、別々の要素として同じ位置に重ねる。** 1 要素で L 字を描かない
- **どの行にも曲がりがある。** 最後の行だけではない
- **最後の行では、通し線を出さない**（肘で止まる）
- **罫線文字（├ └ ┣）を使わない。** 読み上げに乗り、字幅がフォントで変わる
- **太さ・濃さで階層を表さない。** 階層は字下げが表す
- 🚨 **曲がり半径と間隔は暫定。** 堀池さんの実測値待ち（§5）

---

## 1. 撤回した結論 —「曲がるのは最後の1本だけ」は誤りだった

2026-08-15 の朝まで、この規約にはこう書かれていた（**消さずに残す**。消すと同じ結論が作り直される）:

> 角丸は「線が曲がる」ところにしか入らない。┣ は曲がりではなく分岐である。
> 縦線が通り抜けながら途中から枝が出る形なので、丸めると縦線か枝のどちらかが途切れる。
> → **曲がるのは最後の1本だけ**

**これは「1 つの要素で L 字を描く」前提でのみ正しかった。前提が違った。**

堀池さんが提示された実物は、**両立していた**:

```
.ytSubThreadConnection    肘。border-left + border-bottom + 左下だけ角丸
.ytSubThreadContinuation  通し線。角丸なし。そのまま下へ抜ける
→ 同じ位置に 2 つ重ねるので、縦線は途切れず、枝は丸い
```

🚨 **「できない」と言う前に、それをやっているものを探すこと。**
design は「両立しない」という結論をそのまま受け取って実装し、**自分では探さなかった**。

## 2. 描き方（OhMyCMS の実装）

要素を増やさず、`li` の擬似要素を役割で割り当てている（`app/globals.css`）。

| 役割 | 何を描くか | どこに出るか |
|---|---|---|
| `::before` 通し線 | 上端から下端まで、まっすぐ。**角丸なし** | 🚨 **最後の行には出さない** |
| `::after` 肘 | 上端から行の縦中央まで下り、**左下で曲がって**右へ枝 | **どの行にも出る** |

肘は `border-inline-start` + `border-block-end` + `border-end-start-radius` の 3 つで描く。
通し線と同じ位置に重なるので、**途中の行でも縦線は途切れない**。

使う側はクラスを覚えなくてよい。`data-slot` だけで効く:

```html
<ul data-slot="tree">
  <li data-slot="tree-item">…</li>   <!-- 通し線 + 肘 -->
  <li data-slot="tree-item">…</li>   <!-- 最後の行は通し線が出ない -->
</ul>
```

## 3. 禁止

- ❌ **罫線文字（├ └ ┣ │）を使う** — 読み上げに乗る。字幅がフォントで変わる
- ❌ **太さ・濃さで階層を表す** — 階層は字下げが表す（二重符号化しない）。
  濃さを深さで決めると、**何段まで薄くするかの上限が決められない**（段数は無限に増えうる）
- ❌ **面の角丸（`--radius`）を流用する** — 面の角丸は**面の大きさ**に比例し、
  線の曲がりは**枝の長さ**に拘束される。**制約が別物**なので、流用すると
  面のデザインを変えた瞬間に**曲がりが黙って切れる**
- ❌ **`em` 連動にする** — フォントで 0.26〜0.33em とばらつき、字下げ(px)とズレて
  **階層が下がるほど縦線が揃わなくなる**
- ❌ **字下げを `calc(枝長 + 間隔)` で導出する** — `var()` は**宣言した要素で解決されてから継承される**ので、
  あとから間隔だけを上書きしても**字下げが変わらない**。**独立した値として持つ**

## 4. hover と active

🚨 **`hover:` を書いたら、必ず `active:` も書く**（堀池さん 2026-08-15。
選択時に濃くする指示と同時に出された条件）。
タッチの端末には hover が無い（Tailwind v4 の `hover:` は `@media (hover: hover)` の中）ので、
`active:` が無いと **SP では押しても何も変わらない**。

濃さは **hover と同じ**にする。押し込みの手応えは `components/ui/button.tsx` の base が持つ
`active:not-aria-[haspopup]:translate-y-px`（1px 沈む）が担当している。

🚨 **ただし、これは `Button` を使っている要素にしか当てはまらない**（2026-08-15 追記）。
素の `<tr>` / `<div>` / `<button>` は**沈み込みを継承しない**ので、
**色だけが押した手応え**になる。そこで `active:` を `hover:` より**薄く**すると、
**PC では「押すと手応えが弱くなる」**という逆向きになる。

実測（配信 CSS を読んだ・2026-08-15）:
```
hover:bg-muted      → background-color: var(--muted)                                （100%）
active:bg-muted/80  → color-mix(in oklab, var(--muted) 80%, transparent)             （**薄い**）
```
＝ `<tr>` や素の `<button>` に付いていた `hover:bg-muted active:bg-muted/80` は、
**押すと薄くなる**形だった（4 ファイル・6 箇所）。

**判断の順序:**
```
① その要素は Button か → **はい** … active は hover と同じでよい（沈み込みが手応えを持つ）
②                     → **いいえ** … 🚨 **active は hover と同じか、より濃く**。薄くしない
```
🚨 **「濃さは hover と同じ」を、沈み込みの無い要素へそのまま当てない。**
規約を書いたときに、この範囲の条件を書いていなかった。
🚨 実測（2026-08-15・base2）: 押下時に `translate` が **`0px 0.983px`**（`transition-all` の途中）。
**`transform` ではなく `translate` プロパティ**に入るので、`transform` を読むと永久に `none` に見える。

## 5. 🚨 未決 — 値はまだ決まっていない

| 項目 | いまの値 | 状態 |
|---|---|---|
| 曲がり半径 | `--tree-turn` = 8px | 🚨 **暫定。堀池さんの実測値待ち** |
| 枝の水平長 | `--tree-branch` = 16px | 暫定 |
| 罫線↔テキストの間隔 | `--tree-label-gap` = 4px | 🚨 **未決**（4px / 12px のどちらか） |
| 字下げ | `--tree-indent` = 20px | 暫定 |

**なぜ決まっていないか**: 実物の**効いている**半径がまだ測れていない。

```
実物のページには届いた（title「Me at the zoo - YouTube」/ コメント欄の器 2 件 / 同意画面 0）
🚨 しかし .ytSubThreadThreadline は 0 件 ＝ **見ていない 0**
   （返信欄はスクロールと「返信を表示」まで DOM に出ない）

提示された CSS を写した fixture は **忠実ではなかった**:
  レール 24×80 ／ 肘 x=12 w=12 h=24 ／ 通し線 x=23 w=1 h=80  → **11px ずれて再現された**
🚨 忠実でない模型の数値を「実物の値」として記録に残すと、次の人がそれを正として使うので、採用していない
```

**決め方**: 堀池さんに、返信が 2 件以上あるコメントを開いた状態で
`getBoundingClientRect` と `getComputedStyle`（radius / width / height / left / right）を
コンソールで採っていただく。**1 回で確定する。**

🚨 **値が来たら `--tree-turn` などを差し替えるだけで全体が追従する**形にしてある。
**構造は確定・値は差し替え可**という状態。
