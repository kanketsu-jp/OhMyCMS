## 決定

1. **アップロードの失敗は、2 つの上限に分けて返す。**

```
① アプリが決めた上限（MAX_UPLOAD_SIZE = 50MB）を超えた
   → 413 FILE_TOO_LARGE「ファイルサイズは50MB以下にしてください」
   🚨 本文を読む前に content-length で弾く
② 本文そのものを読み切れなかった
   → 413 UPLOAD_BODY_UNREADABLE「アップロードの内容を読み取れませんでした」
   🚨 **数字を書かない**
```

2. 🚨 **②に「50MB 以下にしてください」と書かない。**
   **上限より小さくても落ちるので、嘘になる。**

3. **`MAX_UPLOAD_SIZE` は 1 箇所に置き、ルートと service が同じ値を使う。**
   （2 箇所に書くと、**通す門と落とす門が食い違う**）

## なぜ（2026-08-16 の実測）

### 上限の判定に、一度も到達していなかった

```
50MB 超を送る → 🚨 HTTP 500 / INTERNAL_ERROR
サーバのログ: [api] 未処理の例外: "TypeError: Failed to parse body as FormData."
＝ request.formData() が先に落ち、service.ts の 50MB 判定へ届いていない
```

🚨 **`FILE_TOO_LARGE` は書いてあるのに、画面へ出たことが一度も無い文言だった。**
利用者に出ていたのは「サーバ内部でエラーが発生しました」で、
**自分が悪いのか、こちらが壊れたのかを区別できない。**

### 🚨 そして上限は 50MB ではなかった

```
1 / 5 / 6 / 7 / 8 / 9MB     → 🟢 201
9.996 / 10 / 20 / 40 / 49MB → 🚨 500
＝ 9MB と 10MB のあいだで落ちる
🟢 proxy.ts は本文に触れていない（実測 0 件）＝ ここが原因ではない
```

**アプリは 50MB を許すつもりで書かれているが、そこまで届かない。**
**2 つの上限が在り、小さいほうが先に効く。**

### 直したあとの実測

```
51MB → 413 FILE_TOO_LARGE
12MB → 413 UPLOAD_BODY_UNREADABLE
🟢 対照 5MB → 201（普通のアップロードを壊していない）
```

## この決定が答えないこと

- 🚨 **本番ビルド（:3101）では未測定**。`dev-login` が本番に無いため、セッションを作れず
  同じ測定ができていない。**開発サーバだけの制限かどうかは分かっていない。**
- 🚨 **10〜50MB のファイルをどうするかは決まっていない。**
  いまは「読み取れませんでした」としか言えず、**利用者に次の手が示せない**。
  上限を実態へ下げるのか、経路を直すのかは**持ち主の判断**。
- 🚨 **`FILE_TOO_LARGE` / `UPLOAD_BODY_UNREADABLE` は `i18n/error.ts` の表に無い。**
  そのため画面では**理由が消えて**一般的な文言になる（実測: 英語画面で
  "Failed to upload file"）。表への追加は別の担当が持っている。

## やらないこと

- ❌ ②の文言に上限の数字を書く（上限より小さくても起きる）
- ❌ `MAX_UPLOAD_SIZE` をルート側にも別途書く（食い違う）
- ❌ 本文を読んでから大きさを判定する（読めないから落ちている）
- ❌ 「50MB まで使える」と案内する（**実測が届いていない**）
