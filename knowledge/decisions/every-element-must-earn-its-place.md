# 画面に置くものには理由が要る（枠・常設・背景・寸法）

> 由来: 2026-08-15 堀池。`.temp/2026-08-13/idea.md` の「v2.5 → ブラッシュアップ内容」。
> **4つの指摘は別々に見えるが、根は1つ**——「**それを置く理由を言えるか**」。
> [[no-nested-surfaces]] を**否定しない。より厳しくする**（あちらは「面は1段まで」、
> こちらは「**そもそも1段目を作る理由があるか**」）。

## 決定

**画面に足すものは、なぜそこに要るかを言えるときだけ足す。** 言えないものは外す。
判断の型を4つ、下に置く。**どれも「理由が言えるか」を聞いている。**

---

## 1. 枠は「別の領域」を意味する。節が1つなら付けない

> 堀池（原文）:
> 「ボーダー＋Padding はいらない。親要素にすでに Padding があるのと、
> **カードコンポーネントを多用するのはデザインスキルが低い**。理由として、
> **枠というのは明確な別の領域を表現する**が、いまの … section はそもそも
> コレクションページの最初の表示する要素（データテーブルでコレクション一覧）があるのに、
> それをボーダー＋角丸でカードタイプにしてしまうので、**同じ領域の関連する
> （というかもはやメインの）要素なのに、そのセクションを分けて表現しているのが未熟**。
> この場合コレクション一覧しかセクションがないので、ボーダーも Padding も必要ない。
> **ただし、2つ要素が並ぶ場合は、その間に Divider を用意する**。」

- **節が1つしかないページは、枠を持たない**（`Surface` で包まない）
- **節が2つ以上あるときだけ、あいだに Divider**
  - 🚨 **先頭には引かない。** 引くと**すぐ上のヘッダの下辺と2本並ぶ**
    （2026-08-15 実測。見出しを外した瞬間に出た）
  - 実装: `app/globals.css` の
    `[data-slot=surface-container] + [data-slot=surface-container] > [data-slot=surface]`
    （**自分の親の中での順番は、その要素自身の class では表現できない**）
- **同じ領域の中の要素を枠で分けない。** 枠で分けてよいのは「別の領域」だけ

## 2. 常に見えているものは、常設に足る理由を持つ

> 堀池（原文）:
> 「… header > div.hidden.text-sm.text-muted-foreground.md:block は廃止。
> **メアドを表示するいみがない**。…
> 「**常に表示するものはそれなりの理由・必要性がいる。
> メアド＝今だれがログインしているか？は必要ない。左サイドバーでOK**」」

- **常設の領域（ヘッダ・サイドバー）に置くのは、毎回要るものだけ**
- 「あると便利」は常設の理由にならない。**置き場所は他にある**（個人設定・右サイドバー）
- 🚨 **ページの見出しと概要も常設ではない。**
  タイトルは**パンくず**へ、概要は **info アイコン（右サイドバー）**へ。
  文言は消さず `lib/admin/page-meta.ts` に**辞書キー**として持ち、
  パンくず・右サイドバー・Storybook・LLM がそこから読む

## 3. 変えられない値を、入力欄に見せない

> 堀池（原文）:
> 「変更できない ID などはそもそも背景を Input タグと同じにしない。（背景なし）…
> ID は必ず必要で変更できないのに、背景が `.bg-muted/60` なので、**編集できると思ってしまう**。
> **これは UIUX で絶対にやってはいけないこと。なんのために Variant があるのか理解して。**」

- `readOnly` の入力は**塗りも罫線も持たない**。ラベルの下に置かれた**文字**として見せる
- 🚨 **`disabled` とは別物。** disabled は「いまは使えない」、readOnly は「**そもそも変えられない**」。
  色分けを共有しない
- 実装は **`read-only:` 修飾子**（`components/ui/input.tsx`）。**prop を足さない**ので付け忘れが起きない
- **`<input>` のまま残す**。ID は**なぞって選択・コピーできる必要がある**
- 機械で見る: `audit-surface-depth.mjs` の `§3 変えられない値が入力欄に見えている`

## 4. 寸法は Tailwind の標準値から選ぶ

> 堀池（原文）:
> 「すべて TailwindCSS の値をつかう。**独自の `text-[11]` などはひかえて、`text-sm`,`text-base` など。**」

- **文字サイズ・余白・高さは標準値**（`text-xs` / `text-sm` / `text-base` …）
- 🚨 **「独自値をすべて消す」ではない。** 2026-08-15 の実測では 39 件のうち、
  **標準値へ直せたのは 2 件だけ**だった。残りは:

  | 種類 | 例 | なぜ残すか |
  |---|---|---|
  | shadcn の部品定義 | `rounded-[min(var(--radius-md),10px)]` | **上流の定義**。触ると更新のたび衝突する |
  | ビューポート・環境変数 | `max-h-[84vh]` / `pb-[env(safe-area-inset-bottom)]` | **標準値が存在しない** |
  | グリッドの列指定 | `grid-cols-[1fr_220px_auto]` | 標準値では表現できない |
  | アニメーションの移動量 | `translate-y-[2.5rem]` | 同上 |
  | 属性セレクタ | `data-[state=open]` | **そもそも独自値ではない**（数に入れない） |

  → **数える前に、何を数えているか生の出力で確かめる。**
    属性セレクタを混ぜると件数が倍近くになり、「独自値だらけ」という誤った像になる

## 5. Variant を足すときの落とし穴（実測）

### 🚨 `size` という prop 名を、ネイティブ要素を包む部品に足さない

> 2026-08-15 実測。入口用の大きさを `size="entry"` として `Input` に足したらビルドが落ちた。
> **`<input size>` はネイティブ属性で、型は `number`**。
> `React.ComponentProps<"input">` を素通しする側（`input-group.tsx`）が型検査に落ちる。

- **`variant` を使う。** shadcn が `Button` に `size` を使っているので**手が勝手に `size` と書く**。
  包んでいるのがネイティブ要素なら、その要素の属性表を先に見る
- 同じ罠: `<a href>` を包む部品の `href`、`<form action>` を包む部品の `action`

### 🚨 「大きくする」規則には、必ず上限と理由を書く

`--control-h-entry` は **56px（44px の 1.27 倍）**。
> 堀池:「**大きいと言っても極端に大きくないように。このサイズの Variant やルールは決めておく。**」

**「大きくしてよい」だけの規則は必ず広がる。** どこまでか・なぜそこで止まるかを同じ場所に書く。
（64px 以上は「極端に大きい」側に入る、と決めた）

### 🚨 横断的な変更のあとは、検査の対照を当て直す

> 2026-08-15 実測。他ペインが `next/font/local` を入れ、computed の書体が
> `notoSansJP`（**空白もハイフンも無い生成名**）になった。
> 書体の検査は「Noto Sans JP」という**人が読む綴り**しか知らず、**全ページで誤報**した。

**昨日まで正しかった検査は、測っている対象の形が変わった瞬間に嘘をつき始める。**
検査を触ったときだけでなく、**フォント・トークン・ビルド設定のような横断的な変更のあとにも**
陰性対照（当たっている画面）と陽性対照（当たっていない画面）を当て直す。
関連: [[checks-must-declare-blind-spots]]

**同じ形をもう1つ**（2026-08-15・toast ペインの実測）:
Tailwind v4 は**ソースに現れたクラスしか出力しない**ので、実行時に注入した
`class="bg-emerald-50"` は `rgba(0, 0, 0, 0)` として計算される。
🚨 **「色が当たっていない」ように見えるが、当たっていないのは測り方のほう。**
実行時に色を見るなら、クラス名ではなく `var(--color-*)` を解決する。

**書体の件と構図が同じ**——どちらも「**測る対象の形が変わったのに、測り方が古い**」。
**「壊れている」と「測り方が違う」を、報告する前に必ず切り分ける。**

### 🚨 「これは検査になっていない」という指摘こそ、まず自分で測る

> 2026-08-15。「`bun run lint` は "No files to lint." を返すので、合格の根拠にした人は
> 何も測っていない」という指摘を受けた。**本当なら受入がすべて無効になる**ので測った:
> `bunx eslint`（引数なし）も `bunx eslint .` も **311 ファイル**で同一だった（ESLint 9 の
> flat config は引数が無いとき cwd を解決する）。**このリポジトリでは再現しなかった。**

指摘が正しければ土台が崩れる、という種類の報告ほど**受け取った側が測る**。
🚨 **信じて直すのも、否定して無視するのも、どちらも測っていない点では同じ。**

## この決定が置き換えたもの

- `docs/design/surface-rules.md` は [[no-nested-surfaces]] へ移動済み（このリポジトリには無い）
- **矛盾しない。** [[no-nested-surfaces]] は「**面を2段にしない**」、こちらは
  「**そもそも1段目を作る理由があるか**」。**こちらの方が先に効く**

## アンチパターン

- ❌ 節が1つしかないのに `Surface` で囲む
- ❌ 先頭の面にも Divider を引く（ヘッダの線と2本並ぶ）
- ❌ readOnly に `bg-muted/60` を当てる（**編集できると誤解させる**）
- ❌ 「常設にあると便利だから」で header / sidebar に足す
- ❌ 独自値を機械的に全部つぶす（**shadcn の部品が壊れる**）
- ❌ `data-[…]` を「独自値」として数える
