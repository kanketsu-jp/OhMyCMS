## 決定

利用者のアバターは **SSO のプロフィール画像 → 利用者が選んだ絵文字 → 既定の絵文字** の順で出す。
**メールアドレスから頭文字を作らない。**

## なぜ

堀池さん（`.temp/2026-08-13/idea.md` L36・原文）:
> 「ユーザーのアイコンは絵文字にして。もちろん Google などの SSO を使う場合はそのプロフィール画像にする」

🚨 **直す前は、アバターがメールアドレスの1文字目を出していた**
（`components/admin/user-menu.tsx` の `label.slice(0, 1).toUpperCase()`。`label` は `userLabel`＝メール）。
**メールを画面に出さないための仕組みが別にあるのに、頭文字という形で漏れていた。**
絵文字にする作業の半分は、この静かな経路を消すことだった。

## どう作ったか

| 置き場所 | 理由 |
|---|---|
| `directus_users.avatar_emoji`（**varchar(32)**・nullable） | 利用者ごとの値なので利用者の行に持つ |
| 一覧は `lib/admin/avatar-emojis.ts` の**1本だけ** | 画面と API が同じものを見る。**画面で絞ってサーバが何でも受ける形にしない**（`AGENTS.md` §3.5） |
| 既定の絵文字は `lib/admin/user-label.ts` の定数 | 🚨 **辞書に入れない**。記号は言語で変わらない（`components/admin/shortcuts.ts` の `MOD_SYMBOL` と同じ理由） |

🚨 **列の長さを 1〜4 にしないこと。** 絵文字は肌の色や ZWJ の合成で**複数コードポイント**になる。
実測: `👩‍💻` は `1f469 / 200d / 1f4bb` の **3 つ**。短い列にすると**保存はできたのに文字が壊れる**。
一覧には合成絵文字を意図的に4個入れてある（`🧑‍💻` `👩‍💻` `👨‍🍳` `🐻‍❄️`）——**短くされたら壊れると分かるように**。

## やらないと決めたこと

- **頭文字を作る仕組みを新設しない。** 絵文字にする以上、要らない。
  参考にした別プロジェクトは `avatar-initials.ts` でメールの1文字目を見ており、
  先方自身が「**2本目の静かなメール経路だった**」と認めている
- **「既定に戻す」ボタンを作らない。** 既定の 🙂 が一覧に入っているので、**同じことが1タップでできる**
  （`every-element-must-earn-its-place`）
- **選択中を塗らない。** `✓` で示す（塗ると面が1段増える。憲章 §3b）

## 🚨 内部の管理者にも変えさせる

`local-admin@localhost` を「画面に出さない」からといって、**変更を拒否しない**。
2026-08-15 に `PATCH /api/auth/me` へ `LOCAL_ADMIN_EMAIL` の拒否を入れ、
**本番で堀池さんがアイコンを変えられなくなった**（`40d9eb3` で外した）。

**画面に出さないのはメールアドレスという文字列だけ**で、**その人は実在して、実際に操作している**。
表示の規律を、権利を奪う根拠にしない。
