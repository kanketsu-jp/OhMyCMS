**原典との逐語一致を成果にしない。** 下の 3 件は**意図的に外しており、実装漏れではない。**

🚨 **ただし ② だけは決着していない**（PC でどうするかは原典に書かれておらず、堀池の判断待ち）。
**①と③は決着済み、②は「いまの実装がこうなっている」という記録**——**この違いに注意すること。**

🚨 **原典を「仕様書」として読まないこと。** 原典は堀池が作りたいものを書いた文であって、
**書かれた通りに作ると壊れる箇所がある**（下の 3 件がそれ）。

## 3 件

### ① メタ情報を「全て」格納 → **秘密を除いて**格納

| | |
|---|---|
| 原典 | L82② 取り込み元の**メタ情報を全て**格納する |
| 実装 | **利用者に見せてよいものだけ**を `metadata` に入れる |
| 理由 | 🚨 **`metadata` の列は API に載る**。アクセストークンを入れると、
DevTools・キャッシュ・レスポンスログから読める |
| 理由の在処 | `apps/studio/lib/drive/import.ts` の `DriveSource` 型の直上
（「アクセストークンはこの関数の中だけ。戻り値にも metadata にも入れない」） |

**「全て」を字義どおりに実装すると、認証情報の漏えいになる。**
（グローバル規約「クライアントに返るオブジェクトに access token を載せない」と同じ理由）

### ② モーダルは「画面いっぱい」 → **SP だけ**（PC は中央）

| | |
|---|---|
| 原典 | L102② モーダルは**画面いっぱい**に出す |
| 実装 | **SP は全画面 / PC は中央**（`sm:` から中央寄せへ戻す） |
| 理由 | 🚨 **PC まで全画面にすると、ファイル選択・コマンドパレット・確認ダイアログまで全画面になる**。
「はい / いいえ」を聞くだけの箱が画面を占める |
| 理由の在処 | `apps/studio/components/ui/dialog.tsx`（`sm:inset-auto …` の直上のコメント） |

🚨 **この 1 件は「測っても解けない」型**（原典の読み方が割れる）。
**PC でどうするかは原典に書いていない**ので、実装が読みを 1 つ選んでいる。
**堀池に聞く以外の閉じ方は無い。**

### ③ ショートカットは「被ってはいけない」 → Tiptap との 2 件は**記録済みの例外**

| | |
|---|---|
| 原典 | L104 ショートカットは**被ってはいけない** |
| 実装 | Tiptap（本文エディタ）と重なる 2 件を、検査が**例外として表示**する |
| 理由 | エディタのキーバインドは**エディタに焦点がある間だけ**効くので、
「被っている」と「衝突している」が同じではない |
| 理由の在処 | `apps/studio/scripts/check-shortcuts.mjs`（`TIPTAP_CONFLICT_EXCEPTIONS` の周辺） |

🚨 **その検査自身が、承認の意味を狭く定義している**——
「**承認済み**」は「これでよい」ではなく「**いま在ることを記録した**」の意味だと書いてある。
**例外にするかどうかは堀池が決める**（既定は空）。
