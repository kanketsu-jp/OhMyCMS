# Artifact の標準（HTML で渡すときの型）

> 由来: 2026-08-13 堀池指示。rag-okf の未決事項 20 件を渡す過程で確定した。
> 「私がそのまま回答を入力 → JSON でコピーしてペーストできるように」「モバイルファーストで」
> 「SP では回答のコピーを画面下部の固定ボタンで」「JSON で、が同時に普通に文字列でもコピーできるように」
> 「**推奨で埋める は廃止**」「空いたスペースにメニューボタンでテーマの切り替えとトップページ」
> 「**一つの HTML を更新して使うことをルールに**」「**なるべく下層ページとして追加していく**」
> 「ヘッダーの 1/20 は、それぞれの下層ページで変わらないといけない」
> 「メインの目次は**対応が必要なもの・対応が終わったもの・よみもの**がある。それぞれすべて一つの HTML にまとめる」
> 「**この名称も汎用的に**。回答がある時のみコピー機能があるが、基本それ以外で何でも HTML にする時は使えるもの」
> 「**読んだページは必要ない**。LLM が都度そのページを『完了』にするのか『削除・アーカイブ』するのか決めて HTML を更新する」
> 「**ロゴなどの情報を入れられるように**。使う側で上書きできるように変数として持ち、ホワイトラベルに対応する」
> 2026-08-13 追記: 「**いまは全ての下層ページが一緒になっている。0/0 など。**」「シンプルに全ての HTML を
> **一つの HTML にまとめて管理する**という設計なので、**明示的に指示がない限り下層ページとして用意する**。
> **ただしそれぞれは紐づいていなくていい。単純に記事が複数あるイメージ。**」
> 「**Zenn を参考に記事一覧なども作成。絵文字を使うのも参考にする。**」（色は変えない）
> デザインのベースは Zenn（`../zenn.md`）。git 管理外・堀池PC専用。
> 関連: `decision-board`（常設の判断待ちボード）／Anthropic 標準の `artifact-design`（**別物**。一般的なデザイン指針）

## 0. 原則（CRITICAL）

### 0-1. 何を HTML にするか

**読ませたい・選ばせたいものは、チャットに長文を書かずにこの型の HTML にする。**
設計の説明・比較・調査結果・判断待ち——**回答の有無を問わず**この型を使う。
チャットに残すのは**結論 1 行と URL だけ**。

- ❌ チャットに状態・根拠・選択肢を長々と書く（流れて消える）
- ❌ 設問を「①〜②〜③〜どうしますか？」と 10 件並べる
- ✅ **1 枚の HTML を公開し、チャットは URL だけ**

### 0-2. 🚨 1 つの HTML を更新し続ける（新しく作らない）

**同じ案件のものは、同じファイルパスへ書き直して再公開する。URL を変えない。**
ブックマークしてスマホで開くため、**URL が変わると内容も回答も分断される。**

- 追加の説明・設問が出た → **同じ HTML に足す**
- 別の切り口の資料が要る → **同じ HTML の下層ページにする**
- 新しい HTML を作ってよいのは、**案件そのものが別**のときだけ

再公開は `Artifact` に**同じ `file_path`** を渡す（別セッションからなら `url` を渡す）。

### 0-3. 🚨 既定は「新しい記事を 1 枚足す」（1 ページを長くしない）

**1 つの HTML の中に記事が複数ある、という設計。** スマホでスクロールが終わらない画面は読まれない。

- **明示的な指示がない限り、新しい内容は `<section data-page="…">` を 1 枚足す。**
  既存ページへ書き足すのは、そのページの続きだと明確なときだけ
- **記事どうしは紐づいていなくてよい。** 順路（この次はこれ）を作る義務はない。
  トップの一覧から好きなものへ入れれば十分
- トップページ（`home`）は**記事一覧だけ**。ここに本文を書かない
- 設問は **5〜6 問でページを分ける**。分ける軸は「決める種類」
- 説明・背景・シナリオも**独立した記事**にする

### 0-3b. 🚨 記事カードには絵文字を 1 つ付ける（Zenn の記事一覧の形）

トップの一覧は **Zenn の記事一覧を参考にした形**にしてある。左に絵文字のサムネ、右にタイトルと 1 行説明。

- **どの記事にも `<span class="nav-card-e">📖</span>` を必ず付ける。** 中身が一目で区別できるようにするため
- 絵文字は**内容を表すもの**を選ぶ（設問=📝 / 決定=✅ / 調査=🔍 / 設計=🧩 / 進捗=📊 / 注意=🚨 / 背景=📖）
- **バッジ（`nav-card-n`）は設問のあるページだけ。** 設問が 0 のページに `0/0` を出さない
  （JS 側でも自動的に隠すが、そもそも書かない）

### 0-4. 🚨 目次は 3 区分に固定する

| 区分 | 中身 |
|---|---|
| **対応が必要なもの** | まだ終わっていないページ（設問・依頼・確認） |
| **対応が終わったもの** | 片づいたが、見返す価値のあるページ |
| **よみもの** | 答えの要らない説明・背景・シナリオ |

**この 3 つ以外の区分を作らない。よみものを別の HTML にしない**（§0-2 の違反例）。

### 0-5. 🚨 終わったページの扱いは LLM が毎回決める

**更新のたびに、終わったページを「対応が終わったもの」へ移すか、削除（アーカイブ）するかを判断する。**
自動で溜め続けない。

| 判断 | 条件 |
|---|---|
| **「対応が終わったもの」へ移す** | 後から見返す・決定の根拠として参照される・回答内容を残す価値がある |
| **削除する** | 前提が変わって無効になった・別ページに統合した・一度きりの確認で残す意味がない |

- **削除するときは、消したことと理由をチャットで 1 行報告する**（黙って消さない）
- 設問ページは JS が全問回答で自動的に「対応が終わったもの」へ移すが、**それは表示上の話**。
  markup 上どうするか（残す／消す）は**次の更新時に LLM が決める**
- 「読んだページ」の記録は**持たない**（2026-08-13 廃止。既読かどうかは判断材料にならない）

### 0-6. ヘッダの件数は「いま見ているページ」のもの

下層ページを開いているとき、ヘッダの `n/all` は**そのページの設問数**（例 `2/5`）。
全体（`7/20`）を出してよいのは**トップページだけ**。設問を持たないページでは件数を隠す。

> 由来: 「ヘッダーの 1/20 は、それぞれの下層ページで変わらないといけない。**合わせるなら一つの下層ページにして**」。
> ページを分けたのに数字が全体のままだと、**分けた意味が消えて「まだ 19 問ある」に見える**。

### 0-7. 推奨は表示するが、一括では入れない

**「推奨でまとめて埋める」ボタンは置かない**（2026-08-13 廃止）。
推奨は選択肢の `推奨` バッジで示すだけ。一括で埋めると、読まずに 20/20 になり、
進捗が「本人が見た件数」を表さなくなる。

### 0-8. ホワイトラベル（ロゴ・名前・色は変数で持つ）

**社外・別ブランドへ出す可能性があるので、ブランド情報をハードコードしない。**
テンプレート冒頭の `BRAND` に集約し、**空なら何も出さない**（既定は無印＝Zenn Blue）。

```js
const BRAND = {
  name : '',   // {{brand_name}}  例 'KANKETSU'。空ならヘッダに出さない
  logo : '',   // {{brand_logo}}  data URI か インライン SVG 文字列。空なら出さない
  color: '',   // {{brand_color}} 例 '#3ea8ff'。空なら既定色
  url  : '',   // {{brand_url}}   ロゴのリンク先。空ならリンクにしない
  note : ''    // {{brand_note}}  フッタの一行（会社名・機密表記など）
};
```

- **色を差し替えると、選択状態・推奨バッジ・ボタン・メーターまで一括で変わる**
  （`--brand` 系のトークンを実行時に上書きするため）
- ロゴは**外部 URL を参照しない**（Artifact の CSP でブロックされる）。**data URI か インライン SVG**
- `{{…}}` は**置換の目印**。実際の値が無いときは**空文字のまま**にする（`{{brand_logo}}` を残さない）

## 1. テンプレートは 1 本

**`assets/template.html` だけを使う。**回答があってもなくても同じもの。

**設問（`.q`）を 1 つも置かなければ、回答まわりの UI（固定フッター・コピー・件数）は
自動で消えて純粋な資料になる。**よみもの用の本文部品（カード・要点ボックス・
横スクロールする表・畳める補足）も同じテンプレートに入っている。
**「資料用テンプレート」を別に作らない。**

```
1. assets/template.html をスクラッチパッドへコピー（ファイル名は案件名）
2. 差し替えるのは 4 か所
     ① BRAND 定数       — ロゴ・名前・色（社内なら空のまま）
     ② FORM 定数        — title と localStorage の key（案件ごとに必ず変える）
     ③ home の .mast と 3 区分の目次
     ④ 各 <section data-page> の中身
3. Artifact で公開 → チャットは URL だけ
```

**CSS と JS は触らない。**

## 2. ページを 1 枚足す（更新の基本操作）

```html
<!-- ① 本体 -->
<section data-page="qb" data-title="B. セクション名">
  <div class="sec-h"><h2>B. セクション名</h2><span>06 – 09</span></div>
  …中身…
  <div class="pager">
    <button class="btn btn-ghost" data-go="home">目次へ</button>
    <!-- 次の記事へのボタンは「順路がある」ときだけ。無ければ目次へだけでよい -->
  </div>
</section>

<!-- ② 一覧に 1 行（設問ページなら list-todo、説明なら list-doc） -->
<button class="nav-card" data-go="qb">
  <span class="nav-card-e">📝</span>                    <!-- 必須。内容を表す絵文字 -->
  <span class="nav-card-t">B. セクション名</span>
  <span class="nav-card-d">このページで何を決める/わかるかを 1 行</span>
  <span class="nav-card-n" data-count="qb">0/4</span>   <!-- 設問があるページだけ -->
</button>

<!-- 説明の記事ならバッジ無し -->
<button class="nav-card" data-go="doc-x">
  <span class="nav-card-e">🔍</span>
  <span class="nav-card-t">調べたこと</span>
  <span class="nav-card-d">1 行で中身が分かる説明</span>
</button>
```

ルーティング・ヘッダ件数の切り替え・進捗集計・完了への移動・コピー対象への参加は**すべて自動**。

### 設問の型（回答が要るときだけ使う）

| 型 | 使う場面 | マークアップ |
|---|---|---|
| **A. 単一選択** | 選択肢が出せる（基本） | `.opt` を並べる。推奨に `<span class="rec">推奨</span>` |
| **B. 単一選択 + その他** | 選択肢に無い答えがありうる | 最後の `.opt` を `value="__other__"` にして `<input class="ti">` |
| **C. 自由記述** | 選択肢を出せない | `<textarea class="ti" data-free="1">` |

### 設問カードに必ず入れるもの

1. **何を決めるのか**（見出し 1 行）
2. **なぜ今決めるのか**（`.q-why` 1 行）
3. **判断に効く事実**（`<details class="facts">` に数字で。**無いなら「未測定」と書く**）
4. **選択肢と、それぞれ選ぶと何が起きるか**（`.opt-e` を必ず 1 行）

🚨 **「どちらにしますか」だけの設問を置かない。**
🚨 **推奨は 1 設問に 1 つまで。**本当に五分なら付けない（付けないことが情報になる）。

## 3. 画面の決まり（触らない部分の意図）

| 位置 | 中身 |
|---|---|
| ヘッダ左 | ロゴ（あれば）／下層ページでは **← 目次へ戻る** |
| ヘッダ中央 | 現在のページ名。トップでは案件名 |
| ヘッダ右 | **そのページの進捗**（トップは全体）／ PC のみコピー／ **メニュー（≡）** |
| メニュー | **テーマの切り替え**（端末に合わせる / ライト / ダーク）と **トップページ（目次）** |
| 画面下（SP のみ） | **全体**の進捗と **回答をコピー**。設問が無ければ丸ごと消える |
| コピー | ボトムシート。**文章 / JSON をタブで切り替えて 1 ボタン** |

## 4. 回答の受け取り方（設問がある場合）

```
01. パッケージ名の scope
    → @kanketsu/rag-okf
```
```json
{ "answers": [{ "id": 1, "q": "…", "answer": "…" }], "unanswered": [7] }
```

- **`unanswered` を必ず見る。**未回答が残っているのに「全部決まった」として進めない
- 回答は**そのまま作業指示の根拠として記録する**（案件のドキュメントへ反映してから着手）
- 「その他」の自由記述は**解釈せず、書かれたまま**扱う。曖昧なら 1 往復して確かめる
- 受け取ったら **§0-5 の判断**（完了へ移すか、消すか）を実行して HTML を更新する

## 6. アンチパターン

- ❌ **同じ案件で新しい HTML を作って URL を変える**（§0-2）
- 🚨 ❌ **よみものや別パターンを「もう 1 枚の HTML」として公開する**
  （2026-08-13 実際にやって指摘された。**3 区分目に入れる**）
- ❌ **トップページに本文を積む / 1 ページに全設問を並べる**（§0-3）
- ❌ 目次に 4 つ目の区分を作る（§0-4）
- ❌ **記事カードに絵文字を付けない**（§0-3b。一覧で区別がつかなくなる）
- ❌ **設問が無いページに `0/0` のバッジを出す**（§0-3b。全部同じに見えて一覧の意味が消える）
- ❌ **既存ページに書き足して 1 枚を長くする**（§0-3。既定は新しい記事を足す）
- ❌ 記事どうしに無理やり順路を作る（§0-3。一覧から入れれば十分）
- ❌ 終わったページを放置して溜める／黙って消す（§0-5。**判断して、消したら報告**）
- ❌ 「読んだページ」の記録を復活させる（§0-5）
- ❌ **下層ページで全体の件数を出す**（§0-6）
- ❌ 「推奨で埋める」ボタンを復活させる（§0-7）
- ❌ ブランド名・ロゴ・色を本文に直書きする（§0-8。`BRAND` に集約）
- ❌ ロゴを外部 URL で読む（CSP でブロックされ、無言で消える）
- ❌ 資料用に別テンプレートを作る（設問を置かなければ同じテンプレートが資料になる）
- ❌ PC で作ってから SP に縮める（素の CSS がモバイル。`min-width` だけで広げる）
- ❌ コピーボタンを「JSON」「文章」の 2 つ並べる（**タブ + 1 ボタン**）
- ❌ `navigator.clipboard` の失敗を握りつぶす（**必ず textarea を選択状態にする**）
- ❌ 固定フッターに `env(safe-area-inset-bottom)` を入れない／`body` の下 padding を忘れる
- ❌ 入力の font-size を 16px 未満にする（iOS が勝手に拡大する）
- ❌ `localStorage` を try/catch で囲まない（例外で全体が死ぬ）
- ❌ これらをリポジトリにコミットする（堀池PC専用・git 管理外）

## 7. レビュー観点

- [ ] **同じファイルパスへ再公開したか**（URL が変わっていないか）
- [ ] 追加分を**新しい記事（下層ページ）**にしたか。トップは 3 区分の一覧だけか
- [ ] **どの記事カードにも絵文字が 1 つ付いているか**（§0-3b）
- [ ] **設問が無いページにバッジ（`0/0`）を出していないか**
- [ ] 終わったページを「完了へ移す／消す」の**どちらか判断したか**。消したなら報告したか
- [ ] 下層ページを開いたとき、ヘッダの件数が**そのページの数**になっているか
- [ ] 設問ごとに「事実（数字）」と「選択肢の効果」が揃っているか
- [ ] 推奨が 1 設問に 1 つ以下か
- [ ] ブランド情報が `BRAND` に集約され、空のときに何も出ないか
- [ ] スマホの実寸で、最後の要素が固定バーに隠れずに触れるか
- [ ] コピーが失敗した場合に手で選択できるか
- [ ] light / dark の両方で読めるか
- [ ] チャット側が結論 1 行と URL だけになっているか
