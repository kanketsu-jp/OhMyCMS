# 受入基準3（MVP ⑤）— 人がブラウザで見る3点

> 🚨 **この手順書は「機械では言えないこと」だけに絞ってある。**
>
> 「GUI から全機能へ**到達できる**」（ナビのリンクが生きている・ログインすれば開く・
> 未ログインなら弾かれる）は **`bun run acceptance --only 3` が機械で判定する**。
> 以前あった6手順のうち、到達の確認はそちらへ移した。
>
> ここに残っているのは **「到達できる」では言えない3点**だけ。
> **「HTML に `<button>` がある」は「押すと動く」ではない**（onClick が繋がっているかは HTML から分からない）。

## 0. 事前準備

| 項目 | 値 |
|---|---|
| 対象 | **開発ビルド**。`http://localhost:3102`（`bun run dev`）または `3103`（studio-acc） |
| ログイン | `/login` の「開発用ログイン」にメールアドレス + 「管理者権限」にチェック |
| 🚨 本番ビルド（3101） | **dev-login が消えているのでログインできない**。環境変数の管理者（MVP ④）が入るまで待つ |

**作るものには必ず `acc-` を付ける。** 最後に消す。

---

## 1. 描画されるか

`/admin` → コレクション → ファイル → 設定 の順に開く。

**合格の見え方**:
- 崩れ・要素の重なり・はみ出しが無い
- **モバイル幅でも読める**（堀池さんはモバイルから見る）
- ダーク / ライトの両方で文字が読める

**ここで落ちたら**: デザイン担当（design）へ。**どの画面のどの部分か**を書く。

---

## 2. 押すと動くか

**機械では絶対に分からない部分。** 実際にクリックして、値が変わることまで見る。

1. コレクションを作る: `acc_manual_articles`
2. フィールドを2つ足す: `title`（string）/ `body`（text）
3. アイテムを1件作って保存し、**一覧に出ることを確認**してから開き直して**値が入っていること**を確認
4. 権限: 設定 → ポリシーで `acc-manual-policy`（管理者権限は**オフ**）を作り、
   `acc_manual_articles` の `read` を足して、別のユーザーへ割り当てる

**合格の見え方**: 各操作でエラーが出ず、**保存した値が開き直しても残っている**。

**🚨 否定形もここで見る**: 別のブラウザ（またはシークレットウィンドウ）でそのユーザーとしてログインし、
- 権限を与えた `acc_manual_articles` は**開ける**
- 権限を与えていないコレクションは**開けない**

——**両方を確認する。片方だけでは意味がない**（「何も見えない」だけかもしれない）。

---

## 3. ファイルがブラウザでどう扱われるか

1. ファイル → 画像を1枚アップロード（`acc-manual.png`）
2. 詳細を開く
3. **`.svg` もアップロードして詳細を開く**

**合格の見え方**:
- PNG は**プレビューされる**
- 🚨 **SVG は画像として描画されず、ダウンロード扱いになる**

> 機械での判定は `bun run acceptance --only 9` が行う（`Content-Disposition: attachment` を検査）。
> ここで見るのは**ブラウザが実際にどう振る舞うか**。

---

## 4. 後片付け

1. `acc_manual_articles` を削除
2. `acc-manual.png` と SVG を削除
3. `acc-manual-policy` を削除
4. **ユーザー行は API に削除の入口が無いので消せない。** 残ることを記録する

---

## 記録の書き方

```
基準3 の目視確認  実施日: 2026-__-__  対象: http://localhost:____  HEAD=_______  [開発ビルド]
 1 描画               OK / NG（NG: どの画面のどこか）
 2 押すと動く         OK / NG
   うち権限の否定形   OK / NG（見える方・見えない方の両方を確認したか）
 3 ファイルの扱い     OK / NG（PNG プレビュー / SVG ダウンロード）
 4 後片付け           完了 / 残ったもの: ______
判定: PASS / FAIL（FAIL ならどれか）
```

🚨 **どの環境（開発ビルド / 本番ビルド）で見たかを必ず書く。** 挙動が違う項目がある。
